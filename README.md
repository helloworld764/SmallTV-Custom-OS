# SmallTV Custom OS

Первый этап: минимальный FastAPI backend и локальный симулятор дисплея 240×240.
Требования проекта находятся в `TZ.md`, правила работы — в `AGENTS.md`.
В подготовленной рабочей копии эти документы сохранены без изменений.

## Структура

```text
backend/app/      API, конфигурация и точка запуска
firmware/         описание будущего аппаратного компонента, без прошивки
web/simulator/   HTML/CSS/JS симулятор, без сборщика и npm-зависимостей
codex-monitor/   описание будущего Windows-агента, без реализации
docs/            архитектура и границы первого этапа
tests/           Python API/config и JavaScript connection tests
```

Название `codex-monitor/` и общие `tests/` выбраны по текущему заданию владельца.
Backend предназначен для Debian; локальная разработка и Codex остаются на Windows.
SQLite, Tamagotchi, Telegram, OTA, реальная прошивка и монитор Codex не реализованы.

## Windows (PowerShell)

Нужен Python 3.11+ с модулем venv. Из корня проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
.\.venv\Scripts\python.exe -m backend.app
```

Активация окружения и изменение ExecutionPolicy не требуются.
Если `py` недоступен, используйте полный путь к установленному `python.exe`.
Для запуска без тестовых зависимостей устанавливайте `backend/requirements.txt`.

## Debian (ручной локальный запуск)

Нужны Python 3.11+, pip и поддержка venv; установка системных пакетов здесь не выполняется.
Из корня проекта, от обычного пользователя:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-dev.txt
.venv/bin/python -m backend.app
```

Это инструкция для разработки, а не развёртывание: systemd, firewall и питание не меняются.

## Backend и симулятор

После запуска откройте:

- `http://127.0.0.1:8000/health` → `{"status":"ok"}`
- `http://127.0.0.1:8000/simulator/` → дисплей 240×240
- `http://127.0.0.1:8000/docs` → OpenAPI

Симулятор обслуживается backend и использует относительный `/health`, без CORS
и отдельного сервера. Не открывайте HTML через `file://`.
По умолчанию сервер слушает только `127.0.0.1`; доступ из LAN не настраивается.
Для просмотра симулятора при запуске на Debian откройте браузер на самом Debian.

Часы — локальное время браузера, не эмуляция NTP/RTC ESP8266.
Индикатор всегда виден, в том числе во время временного уведомления:

- жёлтый — первоначальная проверка, ошибка или данные старше 15 секунд;
- зелёный — свежий успешный ответ API;
- красный — три ошибки подряд.

Проверки идут последовательно: timeout 2,5 с, обычный интервал 5 с,
после ошибок паузы 10/20/30 с. Подтверждение потери связи занимает примерно
30–45 с в активной вкладке; фоновые вкладки могут проверяться реже.
Первый успешный ответ не вызывает уведомление о включении.
Смена подтверждённого состояния вызывает уведомление на 4 секунды;
короткий сбой не вызывает пары уведомлений. Красный означает недоступность API,
а не доказанное отключение питания. Общая очередь событий пока не реализована.

Проверка вручную: остановите сервер через Ctrl+C, оставьте вкладку открытой,
дождитесь красного индикатора и снова запустите сервер. Связь восстановится
автоматически, часы продолжают работать во время отключения.

## Конфигурация

Можно скопировать `.env.example` в `.env` в корне, если `.env` ещё не существует.
Переменные окружения имеют приоритет над `.env`. Все команды выполняются из корня.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SMALLTV_HOST` | `127.0.0.1` | Адрес прослушивания |
| `SMALLTV_PORT` | `8000` | Порт 1–65535 |
| `SMALLTV_LOG_LEVEL` | `info` | critical/error/warning/info/debug |

Пример смены порта на Windows:

```powershell
$env:SMALLTV_PORT = '8123'
.\.venv\Scripts\python.exe -m backend.app
```

На Debian:

```bash
SMALLTV_PORT=8123 .venv/bin/python -m backend.app
```

Health проверяет только работоспособность процесса API. Он не проверяет устройство,
БД, сеть, Telegram или Windows. Ответ не содержит конфигурацию и секреты.

## Автоматические тесты

Windows:

```powershell
.\.venv\Scripts\python.exe -m pytest
node --test tests/simulator.test.mjs
```

Debian:

```bash
.venv/bin/python -m pytest
node --test tests/simulator.test.mjs
```

Node.js 20+ нужен только для JavaScript-тестов; симулятор работает в современном
браузере без Node.js. Тесты проверяют API, конфигурацию, статические файлы,
потерю связи, восстановление, подавление кратких сбоев и ошибки ответов API.

Зависимости заданы допустимыми диапазонами. Полного lock-файла пока нет;
результаты проверки конкретного окружения указаны в `docs/verification.md`.
Сторонний firmware-код не скопирован. Лицензия всего проекта пока не выбрана.
