# Storm OS — уведомления Codex в симуляторе

Это узкая доставка конечных событий в браузерное превью, а не общая серверная
очередь уведомлений, полноценный экран Codex или подтверждение физического показа.
Панель не получила новых элементов управления; изменения ТЗ и миграции не нужны.

## Источник и права

`GET /api/v1/devices/{id}/notifications?after=0` требует пользовательскую сессию
владельца устройства либо super_admin. Device/agent Bearer не заменяет сессию.
Суперадминистратор при просмотре устройства получает события его владельца,
а не свои или события всех пользователей. Для текущего сценария выбираются
все Codex-агенты этого владельца; настройка выбора источника на устройство
ещё не добавлена. Неактивный аккаунт не выдаёт уведомления.

Ответ: `device_id`, `server_time`, `next_cursor`, `events`. В событии только `id`
(agent UUID + event UUID), `cursor`, `kind` и `ttl_seconds`. Имена агентов,
тексты заданий/ответов, команды, credentials и run_id не выдаются. Ответ no-store.
Чужое/несуществующее устройство — 404, отсутствие сессии — 401, неверный курсор — 422.

Читается существующий неизменяемый журнал codex_events, без копирования истории,
добавления таблиц, ACK-записей или удаления записей. Курсор — rowid журнала,
по которому новые события упорядочиваются независимо от совпадения timestamp.
Один read snapshot используется для проверки владельца, верхней границы и страницы.
Журнал текущими API не удаляется; будущая очистка требует пересмотра контракта курсора.

Страница содержит до 20 конечных событий DONE/ERROR/INTERRUPTED; START/WORKING
не создают оверлеи. После заполненной страницы клиент продолжает со следующего
курсора в очередном цикле. При отсутствии следующей страницы курсор продвигается
до последнего события владельца, включая отфильтрованные старые записи.
Если присланный курсор выше верхней границы восстановленной БД, чтение начинается
с нуля; существующая клиентская дедупликация сохраняется.

## TTL и повторы

TTL — 60 секунд от меньшей из occurred_at и received_at. Это не позволяет
поздно доставленному outbox оживить старое уведомление, а клиентскому будущему
времени — увеличить TTL. На границе 60 секунд событие уже не выдаётся.
События с received_at позже часов сервера не показываются. Это консервативное
поведение при переводе часов назад, а не гарантия доставки всех исторических событий.

Точный повтор POST события остаётся идемпотентным в исходном журнале и не создаёт
новый курсор. Курсор и ID защищают от повторного показа при повторе ответа/потере
связи в одной вкладке. Курсор хранится только в памяти; после перезагрузки страницы
свежие события могут быть показаны снова. Exactly-once между вкладками, перезапусками
и физическими устройствами не обещается. Серверный TTL не продлевается повторами.

## Поведение Storm Simulator

В режиме `/simulator/?device=<id>` после успешной загрузки настроек идёт один
запрос уведомлений с той же cookie. Опрос последовательный, с timeout существующего
ApiClient и backoff проверки backend. Без device уведомления не запрашиваются.
401/403/404 очищают очередь, показ и приватные настройки; сетевой сбой сохраняет
ещё живые сообщения только до их TTL. Формат всей страницы проверяется до приёма.

Оверлей показывает фиксированный безопасный текст, не HTML. DONE сопровождается
«Результат требует проверки». Образ Null ожидает референса владельца, не подменён
чужим питомцем. Основной экран не переключается: после закрытия оверлея видны
его актуальные настройки. Индикатор связи остаётся выше области оверлея.

Приоритеты: потеря связи > ERROR > DONE > INTERRUPTED > восстановление связи.
При равном приоритете FIFO; более важное сообщение прерывает менее важное,
которое затем получает только остаток своих четырёх секунд, если TTL ещё жив.
Буфер — до 8 ожидающих сообщений и одно активное, кэш дедупликации — 128 ID.
При переполнении сохраняются более приоритетные/ранние сообщения, без роста памяти.
Время клиента считается через монотонный performance.now; срок привязывается
к началу запроса, чтобы ожидание ответа не продлевало TTL. Отрисовка раз в секунду.

Нет подмены device heartbeat: браузер не выдаёт себя за SmallTV. ONLINE API
и исторический DONE не подтверждают доступность Windows-агента сейчас.

## Проверки и запуск

Python: `python -m pytest tests/test_display_events.py tests/test_integration_http.py`.
JavaScript: `node --test tests/simulator.test.mjs tests/panel.test.mjs tests/branding.test.mjs`.
Используйте интерпретатор своего venv, как в README.

Проверены RBAC, TTL/задержанный outbox/будущее время, повторы, курсор/пагинация,
восстановление курсора, приоритеты, ограничение памяти, потеря сессии и возврат
к основному экрану. Сквозной HTTP-тест отправляет START/DONE, получает проекцию
JS-клиентом и проверяет модель оверлея. Это не визуальная приёмка браузера/SmallTV.

Для ручного просмотра после обычного перезапуска локального backend войдите в
панель, откройте превью устройства и запустите run-task через настроенный Monitor.
Оставляйте вкладку активной; фоновые вкладки могут пропустить короткий TTL.
Эта ручная проверка, Debian и аппаратная приёмка данным этапом не заменяются.
