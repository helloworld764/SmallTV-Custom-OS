# Storm Simulator — превью Tamagotchi

Экран Tamagotchi в `/simulator/?device=<id>` использует настройки выбранного
устройства и питомца вошедшей в панель учётной записи. Состояние читается из
защищённого `GET /api/v1/pets/current`; при смене пользователя, выходе или
потере сессии имя/состояние очищаются. Если профиль не создан, превью объясняет
это без показа демонстрационных данных.

## Кадры и реакции

Обзорные листы Pixel, Byte и Glitch скопированы без преобразования в
`web/simulator/pets/`, доступны по публичным статическим путям и описаны в
`web/simulator/pets/manifest.json`. Эти три персонажа являются общим каталогом.
Изображение загружается в симулятор, только когда выбран экран Tamagotchi.
Canvas выводит имя и подпись через `textContent`, а не HTML.

Реакции FEED/PLAY/SLEEP/WAKE/ADOPT/RETURN выбирают соответствующие состояния
API. Область питомца увеличена до 208×146 внутри 240×240; имя и эмоция стоят
под кадром, индикатор сервера остаётся в заголовке. Короткие реакции показываются
до серверного `expires_at`; повторный GET не
продлевает срок. Если свежей реакции нет, кадр выбирается по серверной эмоции.
Состояния ABSENT и RETURN_AVAILABLE подписываются отдельно. Опрос питомца идёт
последовательно раз в секунду при активном профиле и раз в пять секунд,
если профиль/состояние недоступны; запросы питомца не накладываются друг на друга.
При системной настройке `prefers-reduced-motion` мягкое движение персонажа отключается.

Внутри canvas лист делится на равные трети 3×3, с пропорциональным вписыванием
ячейки. Внешний вид персонажей одобрен владельцем, но разметка остаётся
приближённой геометрией для экранного превью. Это не утверждённые координаты
спрайтов firmware, не оптимизированный набор кадров и не измерение Flash/RAM,
FPS или совместимости SmallTV.

## Null и приватность

Null намеренно отсутствует в `web/simulator/pets/`, JS-каталоге и публичном
manifest. Его оригинал и листы доступны только локальному файлу просмотра из
`assets/pets/review/`; HTTP/static путь к ним не существует. В API нет отдельной
проверки личного entitlement/выдачи Null, поэтому эта реализация её не имитирует.

## Как открыть

1. Запустить backend и войти в Storm Control Panel.
2. Открыть превью существующего принадлежащего аккаунту устройства.
3. Выбрать стартовый экран Tamagotchi. API-профиль питомца должен быть создан;
   если его нет, симулятор покажет соответствующее сообщение.
4. Принять действие через существующий API/следующий интерфейсный этап и
   наблюдать реакцию в симуляторе. Сам симулятор в этом этапе не меняет игру.

Действия ухода, создание питомца из браузера, Telegram, загрузка изображений,
реплики в облачке, отдельная анимация моргания и социальные механики не входят
в этот этап. Общие три листа доступны как ресурсы каталога; персональные
изображения должны получать отдельный owner-scoped media API.

## Проверки

`tests/pet-display.test.mjs` проверяет сопоставление эмоций/реакций, срок реакций,
рендеринг ячейки и отсутствие Null в публичном списке. `tests/test_pet_art.py`
сверяет опубликованные PNG побайтно с одобренными листами, проверяет хеши,
размеры, HTTP MIME и 404 для Null/private assets. Настоящий браузер и устройство
не считаются проверенными этими тестами.
