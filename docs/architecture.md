# Storm OS — текущая архитектура и границы

Возможности реализуются только по текущим заданиям владельца.

Названия продукта: Storm OS (Storm), Storm Control Panel, Storm Simulator,
будущий единый Telegram-бот Storm Bot. SmallTV-Ultra — аппаратная модель.
Ребрендинг согласован в TZ.md v1.2; технические имена и архитектура сохранены.

## Узлы

- Windows: разработка, Codex CLI, в будущем отдельный Codex Monitor.
- Debian: целевой backend FastAPI/SQLite, бот, мониторинг и веб-панель в будущем.
- SmallTV-Ultra: аппаратное устройство для будущей прошивки Storm OS; ревизия и recovery ещё не проверены.
- Браузер: инструмент проверки интерфейса, не аппаратный эмулятор и не игра.

## Минимальный контракт

`GET /health` возвращает HTTP 200, JSON `{"status":"ok"}` и `Cache-Control: no-store`.
Это проверка liveness процесса. Прикладные API находятся под `/api/v1/`.
Недоступность HTTP, другой статус JSON, ошибка декодирования или timeout
считаются неуспешной проверкой. Отсутствие связи не превращается в успешный статус.

Статика находится в `web/simulator/` и доступна через `/simulator/` с того же origin.
Файлы конфигурации и backend не монтируются в HTTP. Секретов пока не требуется.
Конфигурация валидируется при запуске; неверный порт/уровень логирования останавливает запуск.

## Storm Control Panel

`web/panel/` обслуживается через `/panel/` тем же FastAPI-сервером.
Это HTML/CSS/ES modules без сборщика, внешних ресурсов и новых зависимостей.
Общий `WebFiles` задаёт JavaScript MIME для .mjs независимо от Windows MIME mappings.
Публичная страница содержит только оболочку; данные запрашиваются через защищённый API.
Панель восстанавливает сессию, показывает доступные устройства, сохраняет настройки
с CSRF, обрабатывает 401/403/404/422/429, ошибки сети и timeout.
Ответы сервера и названия устройств вставляются как текст, без HTML-интерполяции.
Cookie остаётся HttpOnly; пароль и CSRF не помещаются в localStorage/sessionStorage.
В фоне раз в 30 секунд проверяется сессия, если вкладка активна и форма не в фокусе.
Повторных автоматических запросов изменения данных нет.
Панель предупреждает о несохранённых настройках перед сменой устройства,
обновлением списка, перечитыванием настроек и выходом. Отмена черновика не изменяет БД.

## Интеграция со Storm Simulator

Ссылка из настроек устройства ведёт на `/simulator/?device=<id>`.
Симулятор использует общий JS ApiClient и тот же защищённый маршрут настроек,
с текущей браузерной cookie. Отдельных публичных копий пользовательских данных нет.
JavaScript-клиент проверяет совпадение device_id ответа с запрошенным устройством.
Модель PreviewSettings хранит настройки только в памяти, помечает их устаревшими
при сбое и очищает при утрате доступа. Отсутствие авторизации не выдаётся за
недоступность backend: индикатор по-прежнему определяется публичным `/health`.
В браузере отображаются тема, яркость и стартовый экран. Вместо неподключённых
модулей показывается явная заглушка. Режим без device остаётся автономными часами.
Ни регистрация устройства, ни привязка credentials автоматически не выполняются.

## SQLite

Фабрика приложения сохраняет `Database` в `app.state.database`. На startup
lifespan выполняет миграции в рабочем потоке. Открытых общих соединений нет:
каждая операция открывает соединение на своём потоке и закрывает его.
Контекст `transaction()` обеспечивает commit или rollback всей операции.
Подробная схема и порядок обновления описаны в [database.md](database.md).
Ошибка миграции останавливает startup; `/health` по-прежнему проверяет только
процесс API и не становится проверкой готовности SQLite во время работы.

Локальный модуль backups использует SQLite Backup API и общую проверку миграций.
Backup и verify читают исходную БД через mode=ro. Restore создаёт отдельный файл,
проверяет схему, применяет недостающие миграции в нём и отзывает восстановленные
сессии. Публикация не перезаписывает существующий файл. HTTP-доступ к копиям,
изменение рабочей конфигурации и планировщик не добавлены. Подробнее: [backups.md](backups.md).

Оставшиеся задачи и согласование функций Tamagotchi, Storm Bot и дальнейшего
развития панели описаны в [roadmap.md](roadmap.md).

## Аутентификация и доступ

Локальные аккаунты создаются доверенным локальным кодом. Для первого администратора
есть CLI; публичной регистрации нет. Пароль хешируется PBKDF2-HMAC-SHA256 с солью.
Сессии имеют срок действия и хранятся как хеши случайных токенов в SQLite.
Cookie HttpOnly, SameSite=Strict, host-only; Secure включается для HTTPS через конфигурацию.
Каждый запрос проверяет активность аккаунта, срок сессии и актуальную роль в БД.
Маршруты устройств ограничивают SQL-запросы владельцем или ролью super_admin.
Изменения требуют CSRF-токен текущей сессии. Подробнее: [auth.md](auth.md).

## Ограничения

Аппаратный provisioning, полная админ-панель, мониторинг Debian, общая доставка событий,
Tamagotchi, Telegram, медиа-конвертация, OTA и Codex Monitor отсутствуют.
Каталог firmware содержит только описание будущего компонента. В codex-monitor
есть диагностика, парсер и локальный smoke-мост с outbox/heartbeat/DPAPI.
Есть обёртка run-task для явно запускаемых read-only задач; постоянного
наблюдения за всеми сессиями и службы пока нет: [task-runner.md](task-runner.md).
Нет systemd, установки на Debian, изменения сети или публичного доступа.

Локальные часы в браузере не подтверждают корректность часов ESP8266.
Симулятор не измеряет RAM/Flash и скорость дисплея. Кириллица в браузере
не подтверждает наличие подходящих шрифтов в прошивке.

Backend поддерживает программную привязку устройства по одноразовому коду,
ограниченный Bearer-доступ к своему state и отзыв/замену ключа. Это не аппаратная
идентификация; см. [device-enrollment.md](device-enrollment.md).

Для будущих Windows-агентов добавлены отдельные регистрации/ключи, ограниченная
identity, heartbeat/freshness и отзыв/ротация. Это не мониторинг Codex и не подтверждение активности
Windows. Подробнее: [agent-identities.md](agent-identities.md).

Источник событий изучен по официальной документации; локальная версия CLI в
среде агента не найдена. Предварительный выбор — обёртка над явно запущенным exec,
без обещаний охвата других сессий: [codex-cli-research.md](codex-cli-research.md).
Автономная нормализация проверена только на синтетических потоках и связке с API:
[exec-parser.md](exec-parser.md). Парсер не запускает процессы и не отправляет данные.
Поверх него добавлен loopback-мост с отдельной SQLite-очередью и DPAPI-хранилищем:
[local-monitor.md](local-monitor.md). UI, серверные маршруты и архитектура не менялись.

Сервер принимает события с run_id/sequence, сохраняет историю и проверяет повторы
и переходы. Это ещё не подключённый Codex Monitor и не очередь уведомлений:
[codex-events.md](codex-events.md). Связь и последнее сообщённое состояние разделены.

Следующие отдельные задачи: очередь уведомлений и device heartbeat,
мониторинг Debian. Аппаратные работы — после доставки,
проверки ревизии и безопасного метода восстановления.
