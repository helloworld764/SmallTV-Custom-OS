# Порядок первого подключения SmallTV

Это подготовленная процедура для этапа после доставки, не выполненная прошивка.
Никаких команд erase/write, OTA или изменения GPIO этот документ сейчас не запускает.

## До изменения устройства

1. Зафиксировать маркировку модели/платы, заводскую версию, фотографии разъёмов
   и доступные заводские функции. Сопоставить с [upstream-аудитом](upstream-firmware-audit.md),
   не подменяя идентификацию совпадением корпуса.
2. Определить безопасный способ питания и подключения, наличие USB-UART,
   тип чипа/Flash и вход в загрузчик. Распиновку, напряжения и auto-reset
   подтвердить для конкретной платы. Не делать коротких замыканий по догадке.
3. Прочитать полный заводской образ без стирания. Сохранить минимум две
   защищённые копии, размер, SHA256 и данные ревизии. Образ может содержать
   Wi-Fi/ключи, поэтому не Git, не публичный архив и не чат.
4. Проверить, что копия полная и читается повторно; составить точную процедуру
   восстановления для этой Flash/загрузчика. До проверки recovery запись не допускается.

## Первый программный образ — только после допуска

- Выбрать target/toolchain/драйвер и закрепить версии. Проверить совместимость
  лицензий и сохранить notices фактически взятых компонентов.
- Сначала тест дисплея/кнопки, безопасный boot и диагностика памяти; затем Wi-Fi,
  сохранение конфигурации и повторное подключение. Factory reset не является
  штатным способом лечить краткую потерю сети.
- Подключать существующие экраны по одному. Проверить кириллицу, ориентацию,
  пропорции питомцев, индикатор связи и управление без блокирования UI.
- Только затем device API: проверяемый TLS, отдельный ключ, heartbeat, данные,
  курсоры/TTL/дедупликация, восстановление экрана после оверлея.

## Что измерить и записать

| Проверка | Необходимое доказательство |
|---|---|
| Плата/LCD/кнопка | Ревизия, установленные выводы, ориентация/цвет, debounce |
| Память | Статическая RAM, свободный heap, крупнейший блок и фрагментация на boot/TLS/JSON/изображениях |
| Flash | Реальная ёмкость и разметка, размер приложения/файловой системы, запас |
| Время | Синхронизация NTP, выбранная зона/DST, работа при отсутствии синхронизации |
| Связь | Потеря AP/DNS/TLS/API, backoff, отзыв ключа, перезапуск сервера |
| Хранение | Перезапуск не теряет конфигурацию; нет записи Flash каждый polling-цикл |
| Восстановление | Проверяемая заводская копия и подтверждённый доступ к загрузчику |

Никаких универсальных порогов free heap или обещания OTA до этих измерений.
Полный буфер240×240 RGB565 —115200байт, поэтому сначала построчное/частичное
рисование и измерение нагрузки, а не перенос браузерного canvas целиком.

## Приёмка с сервером

Проверить получение настроек из панели/бота, часовой сон и прогресс питомца,
уведомления Codex без ложного DONE, работу часов/кнопки при недоступном API,
переподключение и безопасность чужих ключей. После этого —72часа эксплуатации
с журналом технических измерений. Это не возвращает удалённый пользовательский журнал.

OTA рассматривается отдельно: нужна подходящая разметка/запас Flash, проверка
образа и доказанный способ восстановления. Если безопасный OTA не подходит,
его оставляют выключенным и используют подтверждённый проводной процесс.
