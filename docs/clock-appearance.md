# Storm OS — оформление часов

В карточке устройства в Storm Control Panel доступен раздел **«Оформление часов»**:

- **Формат:** 24 часа или 12 часов с отметкой AM/PM.
- **Секунды:** показывать или скрывать. Без секунд цифры крупнее.
- **Классический:** приборная карточка с акцентной гранью, крупными цифрами,
  меткой формата, датой и отдельной погодной плашкой.
- **Минимализм:** открытая асимметричная композиция, тонкие крупные цифры,
  короткий цветной штрих и спокойная погодная капсула.
- **Терминал:** консольная шапка `storm@local:~`, строка `$ clock --local`,
  моноширинное время, вывод даты, погодный блок, тонкая сетка строк и курсор.
  Это оформление, а не исполняемая командная оболочка.

Все три стиля используют цвета выбранной темы. У классического и минимального
стилей тонкая линия показывает долю локальных суток по часам/минутам браузера;
при выключенных секундах она не двигается каждую секунду. `LOCAL CLOCK` в терминале
честно обозначает локальные часы: подтверждения NTP/синхронизации устройства нет.
Декорации не закрывают постоянный индикатор API или временные уведомления.

Стиль, формат и секунды выбираются независимо: можно составить свою комбинацию.
Четыре темы экрана, яркость, дата и погодный виджет под датой сохраняются.
Выбор часов не меняет стартовый экран: для просмотра выберите «Часы» и сохраните
настройки. Превью открывается прежней кнопкой устройства.

В Storm Bot откройте **«Мои устройства» → устройство → «Часы»**. Кнопки **«Формат часов»**,
**«Секунды»**, **«Стиль часов»** показывают варианты с отметкой текущего выбора.
Кнопки задают конкретное значение, а не переключают его при каждом повторе.
Старая использованная кнопка не откатывает более свежие настройки из панели.
Для неиспользованной кнопки проверяется исходное значение; при конфликте бот
предлагает открыть свежую карточку. Права и срок 5 минут проверяются на каждом
действии, включая смену выбранного устройства. В боте даже admin управляет только
своими устройствами; административные права HTTP API сохранены.

Основная карточка устройства содержит разделы **«Часы»**, **«Экран»** (яркость и
стартовый экран), **«Оформление»** (тема). Отдельные параметры показываются только
внутри раздела. «Назад» из списка значений возвращает в раздел, ещё одно «Назад» —
в основную карточку. После сохранения и повтора кнопки остаётся текущий раздел.
Отмена произвольной яркости возвращает в «Экран». Старые выданные кнопки параметров
сохраняют проверки доступа и срок; новая схема БД для группировки не требуется.

## API и сохранение

К существующему `GET/PATCH /api/v1/devices/{id}/settings` добавлены поля:

| Поле | Значения | По умолчанию |
|---|---|---|
| `clock_format` | `24h`, `12h` | `24h` |
| `clock_seconds` | JSON boolean | `true` |
| `clock_style` | `classic`, `minimal`, `terminal` | `classic` |

PATCH частичный; остальные настройки не затираются. `false` сохраняется как
явное выключение секунд. Числа/строки вместо boolean, null и неизвестные стили
отклоняются 422 без частичного применения. Сессия/CSRF/RBAC прежние.
Отдельный device-клиент получает те же поля в `GET /api/v1/devices/{id}/state`.
Ни чтение, ни изменение часов не создаёт heartbeat или ACK физического экрана.

Бот использует тот же `save_settings`, симулятор читает настройки через API.
Панель защищает черновик часов наравне с темой/яркостью. При потере сети превью
сохраняет последнюю версию с пометкой устаревания; при отказе доступа сбрасывает её.
Для старого ответа API без новых полей предусмотрены прежние настройки по умолчанию;
неизвестные новые значения не принимаются как успешный ответ.

Время и часовой пояс пока берутся из **браузера**, а не из NTP устройства.
12 AM — полночь, 12 PM — полдень. Это цифровые браузерные часы; аналоговые часы,
произвольные шрифты/компоновка, отдельный редактор цветов и аппаратный рендер —
последующие этапы. Работоспособность на ESP8266 не заявляется.

## Обновление

Миграция `0016_clock_settings.sql` добавляет колонки со значениями по умолчанию,
сохраняя прежний вид существующих устройств: 24 часа, секунды, классический стиль.
Ограничение полей `telegram_device_intents` расширяется через транзакционное
копирование таблицы с сохранением её имени, ID, значений, срока и consumed у старых
кнопок. Предыдущие миграции не редактируются. Новых зависимостей нет.

Остановите backend и бот через Ctrl+C, затем запустите backend:

```powershell
.\.venv\Scripts\python.exe -m backend.app
```

В другом терминале запустите бот:

```powershell
.\.venv\Scripts\python.exe -m backend.app.bot_worker run
```

Обновите панель и симулятор через Ctrl+F5. БД не удалять. В панели поменяйте часы
и сохраните; в боте обновите карточку. Изменение из бота появится в симуляторе
после очередного опроса, а в панели — после «Перечитать с сервера».

Если открытая до обновления вкладка не меняет дизайн, один раз выполните Ctrl+F5
именно в ней, а не только в панели. В адресе авторизованного превью должен быть
`?device=…`; автономный `/simulator/` не читает настройки выбранного устройства.
Под дисплеем в строке «Настройки с сервера» указаны активные стиль, формат и секунды.
Для новых загрузок HTML/JS/CSS отключено браузерное кэширование; ссылки на входной
модуль и CSS симулятора получили новую версию. Рендерер применяет атрибуты стиля
к экрану сразу после чтения API и при локальном обновлении времени.
Связка API → preview → DOM покрыта HTTP- и JavaScript-тестами. Для проверки новых
макетов используется отдельный headless Chrome/Chromium, без доступа к личному
профилю и открытым вкладкам владельца. Старую вкладку после обновления нужно
один раз перезагрузить, чтобы она получила новую разметку и CSS.

Тесты: `python -m pytest` и существующий набор `node --test` из README. На Windows
используйте `.\.venv\Scripts\python.exe`, на Debian `.venv/bin/python`.
Debian здесь не развёртывается; автотесты используют временные БД и тестовый бот,
не реальную рассылку или данные владельца.

Если установлен Chrome/Chromium, `tests/test_clock_browser.py` дополнительно
запускает headless-браузер с собственным временным профилем. Производственные
HTML/CSS и рендерер проверяются во всех 48 сочетаниях: 3 стиля × 4 темы × 2 формата
× 2 режима секунд. Проверяются границы 240×240, наложения блоков, обрезка времени
и различие типографики. В тестовой папке остаются обзорный PNG и JSON с метриками.
Личный профиль Chrome, API, cookie и рабочая БД в этом тесте не используются.
Если браузера нет, только этот дополнительный тест помечается skipped.
