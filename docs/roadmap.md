# Storm OS — выполнение ТЗ и ближайшие этапы

Источник требований: TZ.md v1.2 и AGENTS.md. Это карта реализации, не замена ТЗ.
Наличие Windows-тестов не означает приёмку на Debian или SmallTV.

## Правило согласования функций

По указанию владельца перед разработкой Tamagotchi, Storm Bot и дальнейшим
расширением Storm Control Panel нужно показать полный предлагаемый список функций
**отдельно для каждой платформы**: базовые требования, удобства пользователя,
отложенные возможности и зависимости. Базовые функции и удобства предлагает
разработчик; владелец может добавить свои. Реализация начинается после согласования.
Уже работающая минимальная панель сохраняется. Этот этап не добавляет функции панели.

То, что требует реальной ревизии SmallTV, откладывается до доставки. Адаптер,
заглушка и браузерное превью всегда помечаются и не выдаются за реальное оборудование.

## Приоритеты после текущего этапа

1. **P0 — завершён текущий локальный этап:** резервные копии, проверки и восстановление
   в отдельный файл. Не включать backend на другой машине и не менять рабочую БД.
2. **P1 — безопасная привязка устройств и сервисные идентичности:** одноразовые коды,
   отдельные credentials, отзыв, проверка прав. Программная привязка устройств
   реализована: [device-enrollment.md](device-enrollment.md). Идентичности будущих
   Windows-агентов: [agent-identities.md](agent-identities.md). Сам Monitor ещё
   не реализован. Аппаратный provisioning остаётся
   отложенным. Если понадобится интерфейс панели — сначала согласовать его функции.
3. **P1 — события и состояние источников:** серверный heartbeat/freshness агентов
   реализован без ложных статусов задач. Приём событий и идемпотентный журнал run
   готовы: [codex-events.md](codex-events.md). Далее очередь/TTL/дедупликация доставки, device heartbeat,
   приоритетные оверлеи в симуляторе. Зависит от предыдущих API и идентичностей.
4. **P2 — Windows Codex Monitor:** исследование событий CLI, затем узкий рабочий
   адаптер и интеграция с событиями. Официальное приложение ChatGPT не обещать.
   Документирован предварительный выбор exec JSONL и добавлена безопасная
   диагностика: [codex-cli-research.md](codex-cli-research.md). Версия установленного
   CLI и реальный поток пока не подтверждены; отправляющего агента нет.
   Добавлен независимый автономный парсер с синтетическими тестами:
   [exec-parser.md](exec-parser.md). Его профиль нужно сверить с реальным CLI.
5. **P2 — погода и мониторинг:** бесплатный источник выбрать после проверки условий;
   платформенные измерения Debian согласовывать отдельно, не имитировать реальные датчики.
6. **P2 — Tamagotchi, Storm Bot, дальнейшая панель:** сначала отдельные списки функций,
   затем подтверждённые этапы. Игровые действия должны быть готовы до подключения
   их к боту. Медиа-конвейер должен появиться до приёма пользовательских изображений.
7. **После доставки:** ревизия и заводской backup/recovery → минимальная прошивка →
   интеграция/ресурсы → безопасный OTA при возможности → общая приёмка и soak test.

Персональные Telegram-боты, полноценная браузерная Tamagotchi-игра, VPS,
управление задачами Codex через Telegram и сложные анимации не включаются автоматически.
