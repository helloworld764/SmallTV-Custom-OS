# Storm OS — выполнение ТЗ и ближайшие этапы

Источник требований: TZ.md v1.10 и AGENTS.md. Это карта реализации, не замена ТЗ.
Наличие Windows-тестов не означает приёмку на Debian или SmallTV.

Последнее дополнение: реализованы личные обои в расширенных настройках панели,
приватный каталог на устройство, нормализация PNG/JPEG, черновик и отображение
во всех четырёх стилях симулятора. Контракт: [wallpapers.md](wallpapers.md).
Базовая безопасная обработка изображений готова; загрузка собственных питомцев
пока не подключена. Формат для реального дисплея, ресурсы Flash и передача медиа
по ключу устройства остаются после аппаратной проверки.

## Правило согласования функций

По указанию владельца перед разработкой Tamagotchi, Storm Bot и дальнейшим
расширением Storm Control Panel нужно показать полный предлагаемый список функций
**отдельно для каждой платформы**: базовые требования, удобства пользователя,
отложенные возможности и зависимости. Базовые функции и удобства предлагает
разработчик; владелец может добавить свои. Реализация начинается после согласования.
Уже работающая минимальная панель сохраняется. По прямому дополнению владельца
реализованы переключатель темы сайта и первый серверный игровой движок;
игровой UI пока не реализован. Добавлен первый локальный этап Storm Bot:
аккаунт через код из панели, меню, свои устройства, город и категории будущей
рассылки. Подключение живого Telegram проверяется отдельно с локальным токеном;
подробности и оставшиеся шаги — [storm-bot.md](storm-bot.md).
Список по трём платформам: [functions-for-approval.md](functions-for-approval.md).
Базовый геймдизайн и 72+24 часа согласованы в TZ.md v1.3. Социальные функции
согласованы после основных; это не утверждение о готовности реализации.

То, что требует реальной ревизии SmallTV, откладывается до доставки. Адаптер,
заглушка и браузерное превью всегда помечаются и не выдаются за реальное оборудование.

## Приоритеты после текущего этапа

1. **P0 — завершён текущий локальный этап:** резервные копии, проверки и восстановление
   в отдельный файл. Не включать backend на другой машине и не менять рабочую БД.
2. **P1 — безопасная привязка устройств и сервисные идентичности:** одноразовые коды,
   отдельные credentials, отзыв, проверка прав. Программная привязка устройств
   реализована: [device-enrollment.md](device-enrollment.md). Идентичности будущих
   Windows-агентов: [agent-identities.md](agent-identities.md). Локальный Monitor
   run-smoke/run-task реализован. Аппаратный provisioning остаётся
   отложенным. Если понадобится интерфейс панели — сначала согласовать его функции.
3. **P1 — события и состояние источников:** серверный heartbeat/freshness агентов
   реализован без ложных статусов задач. Приём событий и идемпотентный журнал run
   готовы: [codex-events.md](codex-events.md). Device heartbeat реализован:
   [device-presence.md](device-presence.md). Узкие оверлеи Codex с TTL/курсором
   реализованы: [simulator-notifications.md](simulator-notifications.md).
   Общая серверная очередь и подтверждение физической доставки остаются отдельно.
4. **P2 — развитие Windows Codex Monitor:** узкий рабочий адаптер и интеграция
   с событиями реализованы. Официальное приложение ChatGPT не обещать.
   Документирован выбор exec JSONL и добавлена безопасная
   диагностика: [codex-cli-research.md](codex-cli-research.md). Владелец сообщил
   CLI 0.167.0; штатные реальные потоки и локальная отправка подтверждены.
   Добавлен независимый автономный парсер с синтетическими тестами:
   [exec-parser.md](exec-parser.md). Его профиль проверен с CLI 0.167.0;
   все реальные варианты ошибок и прерываний ещё не проверены.
   Для одного контролируемого реального запуска подготовлен [exec-smoke.md](exec-smoke.md).
   Владелец подтвердил штатный smoke CLI 0.167.0. Добавлен локальный мост с
   outbox/heartbeat/DPAPI: [local-monitor.md](local-monitor.md). Владелец подтвердил
   DPAPI и реальный delivered/connected=true/pending=0. Изолированные тесты проверяют
   отключение/перезапуск API и клиента, потерю ACK и отсутствие дублей/ложного DONE.
   После смены контекста разрешений DPAPI и CLI доступны и агенту. Добавлен
   [run-task](task-runner.md) для явно запускаемых read-only задач, со stdin,
   ERROR/INTERRUPTED и блокировкой общей outbox. Один реальный сквозной запуск
   CLI → DPAPI/outbox → локальный HTTP backend подтверждён. Отслеживание всех
   интерактивных сессий, удалённый транспорт и автозапуск остаются отдельными задачами.
5. **P2 — погода и мониторинг:** бесплатный источник выбрать после проверки условий;
   платформенные измерения Debian согласовывать отдельно, не имитировать реальные датчики.
6. **P2 — Tamagotchi, Storm Bot, дальнейшая панель:** списки и базовый геймдизайн
   согласованы; продолжать отдельными проверяемыми этапами. Игровые действия должны быть готовы до подключения
   их к боту. Медиа-конвейер должен появиться до приёма пользовательских изображений.
7. **После доставки:** ревизия и заводской backup/recovery → минимальная прошивка →
   интеграция/ресурсы → безопасный OTA при возможности → общая приёмка и soak test.
8. **После основных функций:** друзья, визиты, приветствия, виртуальные подарки
   и совместные задания (§8.5 ТЗ), с согласием, видимостью, блокировкой и лимитами.
   Порядок после базовой игры/бота/панели не требует ожидания VPS и не означает,
   что весь социальный этап нужно реализовать сразу.

Персональные Telegram-боты, полноценная браузерная Tamagotchi-игра, VPS,
управление задачами Codex через Telegram и сложные анимации не включаются автоматически.
