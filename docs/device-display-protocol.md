# Device display protocol v1

Подготовка программной части к SmallTV. Реального драйвера дисплея и прошивки
платы пока нет. Существующий браузерный симулятор продолжает использовать сессию;
его адреса и JSON-контракты не изменены.
Машиночитаемые схемы envelopes и проверка соответствия реальным API-ответам:
[firmware/protocol](../firmware/protocol/README.md). Схемы — host-инструменты,
они не устанавливают Pydantic на устройство и не меняют текущую авторизацию.

## Доступ и чтение

Устройство использует собственный `Authorization: Bearer <device-token>`.
Cookie пользователя не требуется и не может изменить владельца данных.
Получение/замена ключа: [device-enrollment.md](device-enrollment.md).
Сервер вне loopback должен быть доступен по проверяемому HTTPS.
Ключи не передаются в URL, логи или командную строку.

| GET | Результат и предел |
|---|---|
| `/api/v1/devices/{id}/display` | schema_version=1, device_id, server_time, poll_after_seconds=5, screen, settings, data; UTF-8 JSON ≤16 KiB |
| `/api/v1/devices/{id}/display?screen=weather` | Данные выбранного разрешённого экрана; скрытый экран →409 |
| `/api/v1/devices/{id}/display/events?after=0` | Только события своего владельца, до20 событий, JSON ≤16 KiB |
| `/api/v1/devices/{id}/display/assets/Pixel/neutral` | STP1 одного публичного кадра128×128, ≤17 420 байт |
| `/api/v1/devices/{id}/display/wallpaper/{uuid}` | Собственные обои STP1 240×240, ≤58 636 байт; `?format=png` оставлен для диагностики |

`display` отдаёт данные только текущего экрана: часы с погодой, подробную погоду,
Codex, питомца или курсы. `monitor` честно сообщает server_monitor_not_connected;
серверный монитор не имитируется. Отсутствующий питомец/погода не становятся
фиктивными успешными данными. В advanced не передаётся редакторский каталог
сохранённых палитр. Расписание, стили и выбранные цвета сохраняются.
`data.asset` питомца указывает относительный маршрут готового кадра. Null и
собственные питомцы в публичный каталог не включены.

401 — ключ отсутствует/отозван/владелец отключён, 404 — чужое устройство,
422 — неверный экран/курсор, 503 — превышение бюджета/ресурсы недоступны.
Данные проверяются повторно после внешнего погодного запроса: отозванный за
это время ключ не получает собранный ответ. Ответы приватные, Cache-Control:no-store.
Клиент может держать текущие ресурсы в ограниченной оперативной памяти,
при отзыве доступа должен очищать приватное состояние. Не записывать ключи в логи.

Чтение не отправляет heartbeat, не изменяет питомца и не управляет устройством.
Heartbeat остаётся отдельным POST `/{id}/heartbeat` с `{}`, не чаще одного раза
за5с. Программный probe намеренно его не отправляет, чтобы не выдавать имитацию
за реальное присутствие SmallTV.

## События и обрывы

Курсор `next_cursor` непрозрачный; хранить принятый курсор и возобновлять чтение.
После восстановления БД он может уменьшиться — сервер сбрасывает завышенный
after. События имеют стабильный id и оставшийся TTL ≤60с: дедупликация, приоритет
ERROR и возврат к исходному экрану описаны в [simulator-notifications.md](simulator-notifications.md).
Не продлевать TTL сетевой задержкой. Не интерпретировать отсутствие событий как DONE.
При потере API связь UNKNOWN/OFFLINE, а не подтверждение отключения питания.
Браузерные дедупликация/приоритеты покрыты отдельными JS-тестами; их перенос
в C++ потребует проверки памяти и времени на плате.

## Программный клиент

Из корня проекта, указав UUID устройства с действующим ключом (превью без ключа не подходит):

```powershell
.\.venv\Scripts\python.exe firmware/tools/device_probe.py --url http://127.0.0.1:8001 --device-id DEVICE_UUID --cycles 12
```

Ключ вводится скрыто. Для сервера используйте `--url https://your-server.example`,
при собственной CA — `--ca-file` с доверенным сертификатом. Отключения проверки
TLS нет. Probe ничего не записывает в backend, не выводит содержимое питомца,
токен или сырые исключения. Завершение0 — все циклы ONLINE;1 — были отказы.
UNKNOWN до первого успеха, OFFLINE после потери ранее подтверждённой связи.
Автотест поднимает настоящий изолированный HTTP-сервер, делает30 циклов,
останавливает/перезапускает сервер и отзывает тестовый ключ. Пользовательская
БД, настоящий бот и физическое устройство в этой проверке не участвуют.
