# Личные обои устройства

В Storm Control Panel: выберите устройство → Расширенные настройки →
Свои цвета и фоны → Мои обои. Выберите PNG/JPEG, при желании задайте название
и нажмите «Загрузить обои». Встроенное превью показывает результат;
«Сохранить настройки» применяет фон к выбранному устройству и его симулятору.
Готовые фоновые варианты остаются доступны. Новых меню бота нет.

## Обработка и доступ

- Вход: PNG или JPEG, до 2 МиБ, до 4 млн пикселей, каждая сторона до 4096.
  Расширение файла не определяет тип. MIME должен совпасть с декодированным форматом.
  Анимации, SVG, повреждённые и чрезмерно большие изображения отклоняются.
- Сервер учитывает EXIF-ориентацию, пропорционально масштабирует с центральной
  обрезкой до 240×240, заново кодирует PNG и удаляет EXIF, ICC и текстовые метаданные.
  Исходный файл и его имя не сохраняются. Итоговый PNG ограничен 256 КиБ.
  Ручного кадрирования и обработки ИИ на этом этапе нет.
- Декодирование выполняется вне потока обработки async-запросов; одновременно
  допускается до двух операций. Не более 10 попыток загрузки в минуту на аккаунт.
- Каталог — до пяти изображений на устройство. Повторный одинаковый результат
  распознаётся по SHA-256 без дополнительного места; каталог других устройств независим.
- Нужна сессия владельца или super_admin, для записи также CSRF. Чужие устройства
  и обои не раскрываются. UUID другого устройства нельзя записать в настройки.
  Клиент принимает только UUID, не CSS и не внешние URL.
- Чтение — приватный API с no-store/nosniff. В браузере используется временный
  blob URL, который освобождается при смене фона, закрытии страницы и отказе доступа.
  При недоступности изображения остаётся безопасная однотонная подложка.

Подложка общая для всех экранов и четырёх стилей, поверх неё наложен цвет фона
с непрозрачностью 65%. На светлой теме это осветление, на тёмной — затемнение.
Яркость реального дисплея и загрузка обоев в прошивку ещё не проверены.

## Хранение и API

Миграция `0024_device_wallpapers.sql` добавляет `device_wallpapers` с PNG BLOB
и лимитер `wallpaper_upload_limits`. Изображения входят в обычную резервную копию
SQLite, не требуют отдельного каталога и не попадают в Git. Вместе с базой и
бэкапами их следует считать пользовательскими данными.

- `GET /api/v1/devices/{device_id}/wallpapers` — метаданные каталога.
- `POST` по тому же пути — сырые байты, Content-Type image/png или image/jpeg,
  необязательный query `label` (1–40 символов). 201 при добавлении, 200 при дубле.
- `GET /api/v1/devices/{device_id}/wallpapers/{wallpaper_id}` — PNG.
- `DELETE` по тому же пути — 204; активный фон защищён ответом 409.
- Прежний PATCH settings: `advanced.backdrop="wallpaper"` и
  `advanced.wallpaper_id` из каталога этого устройства. При выборе готового фона
  ссылка может сохраняться для повторного выбора. Удаление неактивного файла
  очищает его ссылку, сохраняя остальные настройки.

Установка на Windows: `.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt`.
Для локальной разработки на Debian: `.venv/bin/python -m pip install -r backend/requirements-dev.txt`.
Развёртывание Debian этим этапом не выполняется.

Проверки: `python -m pytest tests/test_wallpapers.py tests/test_advanced_panel_browser.py`
и `node --test tests/wallpaper.test.mjs`; полный набор описан в README.
Используются синтетические изображения и отдельные временные базы/профили Chrome.
