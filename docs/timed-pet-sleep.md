# Часовой сон и уведомление о пробуждении

Согласовано владельцем 9 ноября 2026, TZ.md v1.4. Полный сон длится 3600 секунд.
До завершения энергия не прибавляется. По завершении питомец автоматически
просыпается с энергией 100/100; дальше действует расход бодрствования.
Раннее «Разбудить» не даёт прибавки. Во сне сытость убывает на 2 за час,
настроение сохраняется. Cooldown смены сна остаётся 10 секунд.

Карточка бота показывает оставшееся время на момент её получения. «Обновить»
показывает свежий отсчёт; старое Telegram-сообщение само не редактируется.
API дополнен полем `sleep_ends_at` (epoch seconds или null). Симулятор получает
автоматическое пробуждение и реакцию WAKE через прежний API.

Проекция состояния выполняет переход по серверному времени даже при
выключенном worker. Рассылка не записывает игровые показатели и не меняет
время ухода: 72+24 часа и ограничение расчёта длительного перерыва сохранены.
Пока нет нового действия, SQLite может хранить исходное состояние начала сна;
API вычисляет актуальное состояние, поэтому это не означает продолжение сна.

## Уведомление

- Включите «Настройки» → «Уведомления» → общий выключатель **и категорию «Питомец»**.
- После полного часа создаётся одно событие «час сна завершён». Раннее
  пробуждение отменяет его. Согласие повторно проверяется перед доставкой.
- Выключенные события завершаются без отправки и не догоняются после включения.
- Worker проверяет сроки до/после long polling: при нормальной связи доставка
  занимает до одного цикла опроса, а не обещает ту же секунду.
- После простоя более 30 минут от срока пробуждения событие не отправляется.
  При коротком обрыве ответ сохраняется в SQLite. Сетевая неопределённость
  может повторить доставку Telegram, но не сам переход или серверное событие.
- Отвязка очищает очередь; restore отменяет ожидающие события без сброса игры.

Миграция 0012 добавляет `pet_sleep_sessions` и категорию ответа в Telegram.
Уже спящие профили сохраняют начало `sleep_at`: час не начинается заново при
обновлении приложения. Старые события отсекаются от рассылки, а игровой
профиль показывается с учётом реально прошедшего времени.

## Обновление и проверка

Остановите backend **и** bot worker через Ctrl+C. Запустите заново в двух
PowerShell из корня проекта; базу удалять не нужно:

```powershell
.\.venv\Scripts\python.exe -m backend.app
```

```powershell
.\.venv\Scripts\python.exe -m backend.app.bot_worker run
```

Откройте свежую карточку «Питомец», уложите уставшего питомца спать и проверьте
таймер. Раннее пробуждение не должно давать энергию. Для полного цикла оставьте
его спать час с включённой категорией питомца. Не переводите часы Windows и
не редактируйте рабочую SQLite: автотесты проверяют границы без реального ожидания.
