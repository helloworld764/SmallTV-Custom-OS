# Локальная аутентификация и права доступа

Реализована основа локальной веб-панели `/panel/`. Устройство ESP8266 и Windows-агент
не должны использовать пользовательские cookie: их сервисные credentials будут
отдельным этапом. Telegram и публичная регистрация здесь не реализованы.

## Первоначальная настройка

`python -m backend.app.manage create-admin --username owner` из корня проекта
создаёт первого super_admin. Пароль вводится скрыто дважды, длина 12–1024 символа.
Реального администратора при разработке и тестировании агент не создавал.
Команда не принимает пароль аргументом или переменной окружения. Не копируйте
пароль в логи/чат. При существующем super_admin bootstrap отказывает и не меняет
его запись. Самостоятельного сброса пароля в этом этапе нет.

Логины нормализуются в нижний регистр, 3–64 ASCII-символа: буквы, цифры, точка,
дефис и подчёркивание, первый символ — буква или цифра. Публичной регистрации
и команды массового создания пользователей нет. Обычные пользователи в тестах
создаются только на временных БД внутренней функцией `create_account`.

## Сессии

- PBKDF2-HMAC-SHA256, 600000 итераций, отдельная случайная 16-байтовая соль на пароль.
  Проверка выполняется через constant-time compare; для неизвестного логина
  выполняется проверка фиктивного хеша с той же стоимостью.
- Токен сессии: 32 случайных байта, cookie `smalltv_session`; в БД только SHA-256.
- Cookie host-only, HttpOnly, SameSite=Strict, Path=/, Max-Age по конфигурации.
  Secure=false допускается только для текущей локальной разработки по HTTP;
  для будущего HTTPS необходимо SMALLTV_COOKIE_SECURE=true.
- Срок по умолчанию 12 часов, без автоматического продления. Каждый запрос
  повторно проверяет роль и активность аккаунта в БД.
- Повторный успешный вход заменяет сессию текущего браузера; выход отзывает её
  в БД. Повторное предъявление старой cookie получает 401.
- Авторизованные ответы и ошибки API имеют Cache-Control: no-store.

На входе до хеширования применяется сохраняемый в SQLite минутный лимит:
5 попыток на логин, 10 на адрес клиента. Считаются успешные и неуспешные попытки.
При превышении — 429 и Retry-After: 60. Клиентский адрес берётся из ASGI request,
X-Forwarded-For приложение самостоятельно не использует. При будущем gateway
необходимо отдельно согласовать доверенные прокси и схему ограничения запросов.
Текущая настройка предназначена для локальной работы, не публичного интернета.

## CSRF

Вход требует JSON и нестандартный заголовок `X-SmallTV-Client: web`.
Origin, если присутствует, должен совпадать с origin запроса; cross-site Fetch
Metadata отклоняется. CORS не включён.

После входа API выдаёт CSRF-токен, привязанный к секрету текущей сессии через HMAC.
Его можно повторно получить через GET /api/v1/auth/session. Для PATCH и logout
нужен X-CSRF-Token; другая сессия, отсутствующий/неверный токен и чужой Origin
получают 403. CSRF-токен не является cookie или самостоятельной авторизацией.

## API

| Метод и маршрут | Доступ и результат |
|---|---|
| POST `/api/v1/auth/login` | username/password → user, csrf_token и cookie |
| GET `/api/v1/auth/session` | Текущая сессия → user и csrf_token |
| POST `/api/v1/auth/logout` | Сессия + CSRF → 204 и отзыв cookie |
| GET `/api/v1/devices?limit=50&offset=0` | user: свои; super_admin: все. limit 1–100 |
| GET `/api/v1/devices/{id}` | Только владелец или super_admin |
| GET `/api/v1/devices/{id}/settings` | Только владелец или super_admin |
| PATCH `/api/v1/devices/{id}/settings` | Те же права + CSRF, возвращает сохранённые настройки |

PATCH принимает непустое подмножество brightness (целое 0–100), theme
(BlackArch Red/Dark Blue/Purple/Light), start_screen
(clock/weather/monitor/codex/null/tamagotchi). null, неизвестные поля и попытки
передать owner_id/role отклоняются с 422. Отсутствие сессии — 401.
Чужой и несуществующий ресурс одинаково возвращают 404. Передача чужого id
напрямую не обходит проверку; UPDATE и запись аудита выполняются одной транзакцией.

Логируются создание локального аккаунта, успешный вход, выход и изменение настроек.
В ответах валидации исключены input/ctx, чтобы ошибочный запрос не отражал пароль.
Реальных устройств ещё нет; API сохраняет конфигурацию и не обещает её доставку на ESP.

## Ограничения

Нет MFA, восстановления пароля, полноценной веб-панели, enrollment, управления
пользователями или политики отзыва всех сессий. Лимит попыток не заменяет сетевую
защиту при будущем развёртывании. Настройки не открывают API наружу: bind остаётся
127.0.0.1. systemd, SSH, TLS gateway и Debian на этом этапе не настраиваются.

Ориентиры при реализации: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
и [OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).
