# Собственный питомец: изображение, имя и подтверждение

**Статус: временно отключено по указанию владельца, 12 ноября 2026.**
Сценарии ниже сохранены для будущего восстановления и сейчас недоступны.
Код не удалён: закомментированы импорты/подключение панели, приватного рендера
симулятора и всех API-маршрутов. `backend/app/features.py` содержит закрытый
кодовый флаг `CUSTOM_PETS_ENABLED=False`; его нельзя включить через `.env`/HTTP.
Бот не показывает свои образы/промпт, отклоняет старые кнопки и не скачивает фото.
Старые ответы с пользовательскими образами/промптами не доставляются из очереди.

Таблицы, активные PNG, их превью, исходные модули и тесты сохранены. Миграции
не откатываются. Профиль показывает базовый kind (Pixel/Byte/Glitch) с прежними
именем, игровыми показателями, таймерами и историей; image_id в API равен null.
Обои устройств продолжают работать независимо от этой приостановки.

### Восстановление только по новому указанию владельца

1. Вернуть флаг в `backend/app/features.py` и раскомментировать импорт/регистрацию
   роутера в `backend/app/main.py`. Не пересоздавать/удалять БД и миграции.
2. Раскомментировать CustomPetEditor в `web/panel/panel.mjs` и PrivatePet/приватный
   блок рендера в `web/simulator/simulator.mjs`.
3. Вернуть закомментированный сценарий в `tests/test_advanced_panel_browser.py`;
   согласовать архивную fixture с обычной регистрацией роутера без дублирования.
4. Прогнать проверки, перезапустить локальные backend/worker и обновить страницы.
   Сохранённые активные образы снова станут доступны без повторной загрузки.

Сохранённые API/бот-тесты включают реализацию **только в своих временных приложениях**
через явную fixture `tests/custom_pet_archive.py`. Отдельный набор
`tests/test_custom_pets_paused.py` проверяет безопасное производственное значение
по умолчанию: отсутствие API/UI, неработающие старые кнопки, отсутствие скачивания,
сохранность BLOB и работу базового ухода. Архивная fixture не включает рабочий сервер.

## Storm Bot

«Питомец» → «Создать своего» (либо «Свой образ и имя» у существующего питомца).
Бот показывает один шаблон промпта с местом для описания. Генерация выполняется
пользователем во внешнем инструменте; сервер не подключает платные API или LLM.
Шаблон просит девять отдельных PNG: нейтральный, радость, еда, игра, сон,
пробуждение, голод/грусть, усталость и моргание, с единым дизайном персонажа.
Neutral выдаётся первым и отдельно: сейчас загружается только он, дополнительные
состояния пользователь сохраняет для последующего подключения.
Полный текст оформлен как Telegram `pre`-блок со встроенным копированием:
нажмите значок копирования у блока. Встроенная inline-кнопка `copy_text`
ограничена 256 символами и для полного промпта не используется.

1. Отправьте PNG/JPEG, предпочтительно прозрачный PNG **как файл**, чтобы избежать
   дополнительного сжатия Telegram. Обычное фото также принимается, если подходит по лимитам.
2. Бот покажет обработанный образ и попросит имя — 1–24 символа.
3. Проверьте имя и изображение и нажмите «Подтвердить». До подтверждения текущий
   питомец не меняется. Можно прислать другое изображение или отменить черновик.
4. Новый образ появится в карточке бота и на экране Tamagotchi в авторизованном
   Storm Simulator. На шаги выделяется по 15 минут, просроченный черновик не применяется.

Если питомец уже существует, меняются только его отображаемое имя и образ.
ID, сытость, энергия, настроение, сон, последний уход, номер старта, история
и ожидание возвращения сохраняются. Переименование/картинка не обходят 72+24 часа.
Повторное подтверждение того же черновика не повторяет создание или смену образа.
Подтверждение старого образа после более новой смены не возвращает старую картинку.

## Storm Control Panel

После входа откройте «Свой питомец: изображение и имя» над списком устройств.
Загрузите файл → «Подготовить превью» → имя → «Подтвердить образ и имя».
Кнопка промпта показывает тот же серверный шаблон. Это настройка образа аккаунта,
а не браузерная игра: кнопки кормления/игры в панель не добавлены.
У аккаунта по-прежнему один профиль; его показывают устройства этого аккаунта.
Одновременно хранится один неподтверждённый образ: новая загрузка из панели
или бота заменяет предыдущий черновик, а не действующего питомца.

## Изображения и реакции

- Вход: PNG/JPEG до 2 МиБ, до 4 млн пикселей, максимум 4096 по каждой стороне.
  MIME сопоставляется с фактическим форматом. Анимации, SVG, повреждённые,
  полностью прозрачные и чрезмерно большие изображения отклоняются.
- Общий проверенный декодер обоев используется повторно. Учитывается ориентация
  EXIF, отрезаются только прозрачные поля, сохраняются пропорции и весь персонаж.
  Картинка вписывается в пределы 240×240, заново кодируется в PNG без метаданных.
  Фон непрозрачной фотографии автоматически не удаляется; для силуэта рекомендуется PNG.
- Отдельное превью Telegram 960×960 готовится один раз при загрузке. Чёткие
  границы сохраняются масштабированием NEAREST; Telegram может дополнительно
  сжать sendPhoto. Это не утверждение об аппаратном формате/ресурсах ESP8266.
- Для единственного нейтрального кадра используются существующее спокойное
  движение, короткие значки и подписи действий: еда, игра, сон, пробуждение.
  Новые выражения лица и кадры не генерируются. Настройки уменьшения движения
  и отключения облачков сохраняются. Пропорции отображения и крупный размер
  персонажа в симуляторе сохранены.

## Хранение и безопасность

Миграция `0025_custom_pet_images.sql` добавляет приватные `pet_appearances`,
черновики/квитанции `pet_image_drafts`, лимитер и шаги диалога бота.
Существующие таблицы игры и записи не пересоздаются. Технический `kind`
Pixel/Byte/Glitch сохраняется как базовый тип; у нового профиля со своим образом
используется базовый Pixel, у существующего — его прежний тип. Отображение
определяется новым nullable `image_id`; интерфейс подписывает «Свой питомец».
Общий каталог остаётся Pixel/Byte/Glitch, личные картинки в него не добавляются.
Null из локальных ресурсов не читается автоматически и не публикуется.

PNG и готовое Telegram-превью хранятся как BLOB в SQLite и входят в проверенную
резервную копию. Оригинал, имя исходного файла, EXIF, file_id Telegram и download URL
не записываются. Подтверждение заменяет прежнюю активную картинку с согласия
пользователя; история игры сохраняется. Квитанция сохраняет ID и подтверждённое
имя без дублирования PNG. Лимит 100 подтверждений на аккаунт требует отдельного
решения по архивированию после достижения; данные автоматически не стираются.

Есть session/CSRF и повторная проверка сессии после декодирования. Медиа питомца
доступно только своему аккаунту, включая super_admin без обхода owner scope.
Не более пяти попыток загрузки в минуту на аккаунт, общий декодер ограничивает
одновременную обработку. Черновики истекают через 15 минут; удаляются при отмене,
замене, следующей загрузке, опросе bot worker, отвязке Telegram или restore.
Restore сохраняет активный образ/игру, удаляет неподтверждённые черновики,
шаги диалога и отзывает сессии/привязки по прежним правилам.

До скачивания Telegram-файла проверяются приватный чат, действующая привязка,
шаг диалога и лимит. После I/O они проверяются повторно. Используется только
getFile и HTTPS на api.telegram.org; пути проверяются, редиректы запрещены,
ответ ограничен 2 МиБ и тайм-аутом. Исключения не раскрывают URL с токеном.
Очередь хранит только owner-scoped ID ресурса; перед отправкой приватного
изображения снова проверяются привязка и срок/доступность ресурса.

## API и проверки

- `GET /api/v1/pets/image-prompt` — единый промпт, сессия.
- `POST /api/v1/pets/image-drafts` — сырые байты PNG/JPEG, сессия + CSRF; ID и срок.
- `GET /api/v1/pets/image-drafts/{id}/image` — приватное PNG-превью черновика.
- `POST /api/v1/pets/image-confirm` — `{draft_id, name}`, сессия + CSRF; `{duplicate, pet}`.
- `DELETE /api/v1/pets/image-drafts/{id}` — отмена своего неподтверждённого черновика.
- `GET /api/v1/pets/current/image/{image_id}` — активный PNG своего питомца.
- Прежний `GET /api/v1/pets/current` добавляет nullable `image_id`, остальные поля
  и маршруты сохраняются. Клиент при наличии image_id выбирает приватную картинку.

Профильные тесты: `python -m pytest tests/test_custom_pets.py tests/test_bot_custom_pets.py tests/test_advanced_panel_browser.py`;
JavaScript: `node --test tests/private-pet.test.mjs`. Полный набор — по README.
Используются синтетические файлы/Telegram updates и временные БД/профили Chrome,
без отправки тестовых сообщений в живой бот. Новых зависимостей нет.
Debian, загрузка в прошивку, Flash/RAM и работа на физическом SmallTV не проверялись.

Основание протокола: [Telegram getFile](https://core.telegram.org/bots/api#getfile),
[PhotoSize](https://core.telegram.org/bots/api#photosize),
[Document](https://core.telegram.org/bots/api#document),
[sendPhoto](https://core.telegram.org/bots/api#sendphoto).
Форматирование: [MessageEntity](https://core.telegram.org/bots/api#messageentity),
ограничение короткой кнопки: [CopyTextButton](https://core.telegram.org/bots/api#copytextbutton).
