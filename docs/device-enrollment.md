# Storm OS — программная привязка устройства

Этап реализует backend-протокол и проверку отдельного клиента на Windows.
Он не подтверждает модель, серийный номер, GPIO, прошивку или совместимость SmallTV.
В Storm Control Panel добавлен мастер локального превью и программной привязки.
Аппаратный Wi-Fi provisioning не реализован.
Отдельные credentials Windows-агента описаны в [agent-identities.md](agent-identities.md);
они не взаимозаменяемы с ключами устройства.
Серверный heartbeat устройства реализован отдельно: [device-presence.md](device-presence.md).

## Протокол

| Маршрут | Авторизация | Результат |
|---|---|---|
| POST `/api/v1/devices/enrollment-codes` | Сессия пользователя + CSRF | `{name}` → одноразовые `id`, `code`, `expires_at`; 201 |
| GET `/api/v1/devices/enrollment-codes/{id}` | Владелец кода или super_admin | Состояние pending/enrolled/expired/closed, имя и device_id без кода/ключа |
| DELETE `/api/v1/devices/enrollment-codes/{id}` | Владелец кода или super_admin + CSRF | Отмена кода; 204 |
| POST `/api/v1/devices/previews` | Сессия пользователя + CSRF | `{name, request_id: UUID}` → локальное превью без credentials; 201, повтор 200 |
| POST `/api/v1/devices/enroll` | Одноразовый code в JSON | Атомарная регистрация → `device_id`, `token`; 201 |
| GET `/api/v1/devices/{id}/state` | `Authorization: Bearer <device-token>` | Только собственные `device_id` и `settings` |
| POST `/api/v1/devices/{id}/credentials/revoke` | Владелец устройства или super_admin + CSRF | Отзыв ключа; 204 |
| POST `/api/v1/devices/{id}/credentials/rotate` | Те же права + CSRF | Новый token, старый сразу недействителен |

Код живёт пять минут, содержит 24 случайных байта и может быть использован
только один раз. В SQLite хранится только SHA-256 кода. Одновременно допускаются
пять активных кодов на владельца. Имя устройства задаётся при выдаче кода;
передавать owner_id/role и переопределять владельца при погашении нельзя.

Погашение в одной транзакции создаёт устройство, настройки и credential, помечает
код использованным и записывает аудит. Параллельное погашение одного кода создаёт
ровно одно устройство. Истёкший, использованный, отменённый, неизвестный код и
код отключённого аккаунта возвращают одинаковый 400. Публичный endpoint имеет
лимит 30 попыток в минуту на адрес клиента; счётчик сохраняется и при отказе.

Ключ устройства содержит 32 случайных байта с техническим префиксом
`smalltv_device_`. В SQLite только его хеш; исходное значение выдаётся один раз.
Повторно прочитать его нельзя. Если ответ потерян, владелец должен заменить ключ.
Безопасную передачу нового ключа физическому устройству ещё предстоит реализовать.

Cookie пользователя не заменяет ключ устройства. Ключ не даёт доступа к списку
устройств, auth API, изменению настроек или данным другого устройства. Отключение
аккаунта владельца блокирует также его устройства. Чужой device_id возвращает 404;
отсутствующий/отозванный ключ — 401. Ответ не содержит токенов, owner_id,
учётных записей или глобальной конфигурации.

## Проверка и хранение

Протокол проверен ASGI-тестами и сквозным HTTP-тестом на временной БД.
Для ручного исследования доступны существующие OpenAPI `/docs`; интерфейс панели
описан ниже. Не вводите реальные коды
или токены в чат, Git, URL или логи. Примеры должны использовать placeholders.
Обмен вне доверенной локальной среды требует защищённого транспорта по ТЗ;
TLS, публичный доступ и настройка Debian этим этапом не выполняются.

Резервная копия содержит хеши credentials. При restore-db в новой копии
отзываются пользовательские сессии, ключи устройств и все неиспользованные коды.
Иначе восстановление старой копии могло бы снова активировать ранее отозванный
доступ. Оригинал и сам файл backup при этом не изменяются.

В аудит попадают только типы действий и идентификаторы ресурсов. Коды, Bearer
и пароли не записываются. Автоматической очистки старых кодов/счётчиков пока нет.
Heartbeat, доставка/подтверждение событий, статус реального устройства, заводская
идентификация и provisioning Wi-Fi остаются отдельными этапами.

## Мастер в Storm Control Panel

Войдите в `/panel/`, нажмите **«Добавить устройство»**, укажите имя (1–80 символов).

**Локальное превью — без SmallTV:** создаёт запись вашего аккаунта с базовыми
настройками. Она отмечена «Локальное превью» в списке. Настройте стартовый экран
и нажмите «Открыть превью устройства». Питомец и погода читаются из того же аккаунта,
что и в боте. Действие не создаёт ключ устройства и не отправляет heartbeat:
статус присутствия остаётся UNKNOWN. Ротация device-ключа превью отклоняется 409.
Это сохранённая запись для разработки, а не регистрация физического SmallTV.
Превью видно в обычном списке устройств и в боте; управление его настройками
меняет только серверную запись и браузерное отображение.

Запрос содержит случайный UUID попытки. При потере ответа кнопка повтора использует
тот же UUID и имя; сервер возвращает ту же запись, в том числе после перезапуска.
Другое имя с тем же UUID даёт 409. На владельца не более пяти новых превью за минуту;
повтор успешной попытки не расходует лимит. При закрытии мастера попытка сохраняется
в памяти до обновления страницы. После перезагрузки сначала проверьте список,
чтобы не создать второе превью вручную. Созданные записи автоматически не удаляются.

После переименования устройства повтор с исходным UUID и исходным именем запроса
возвращает ту же запись с её текущим именем. Переименование не создаёт новое превью:
[device-management.md](device-management.md).

**Код для программного клиента:** выдаёт прежний enrollment-код на пять минут.
Панель показывает его только в памяти страницы, без URL и браузерного хранилища.
Клиент погашает код через существующий `POST /api/v1/devices/enroll` и сам получает
свой ключ. Панель не погашает код и не получает ключ клиента. После этого нажмите
«Проверить подключение»: мастер выберет зарегистрированное устройство.
Это проверка регистрации, а не связи/heartbeat или готовности железа.

Кнопка «Отменить код и закрыть» скрывает код сразу и запрашивает отмену на сервере.
Если запрос не подтверждён, можно повторить отмену или явно закрыть без неё:
код истечёт сам. Закрытие вкладки/выход не гарантируют серверную отмену.
При потере ответа выдачи исходный код нельзя восстановить; он истечёт в пределах
пяти минут. Новый запрос выдачи может создать ещё один код в пределах прежнего лимита.
Секрет очищается при истечении таймера, подтверждённом погашении и смене аккаунта.

Миграция `0014_device_wizard.sql` добавляет маркер превью и связь нового погашения
с устройством. Существующие данные и старые миграции сохраняются. Для ранее
использованных кодов связь неизвестна: статус **closed**, без утверждения, что
код был отменён. Для новых погашенных кодов статус **enrolled** сохраняется и
после отзыва ключа: статус регистрации не равен доступности устройства.

После обновления остановите локальные backend и бот, затем запустите backend
обычной командой `python -m backend.app`: миграция применяется автоматически.
Не удаляйте БД. После запуска бота обновите панель через Ctrl+F5.
На Windows используйте `.\.venv\Scripts\python.exe`, на Debian `.venv/bin/python`;
само развёртывание на Debian этим этапом не выполняется.
