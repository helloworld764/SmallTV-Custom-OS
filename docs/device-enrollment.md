# Storm OS — программная привязка устройства

Этап реализует backend-протокол и проверку отдельного клиента на Windows.
Он не подтверждает модель, серийный номер, GPIO, прошивку или совместимость SmallTV.
Мастер в Storm Control Panel и аппаратный Wi-Fi provisioning не добавлены.
Сервисные credentials Windows-агента также пока не реализованы.

## Протокол

| Маршрут | Авторизация | Результат |
|---|---|---|
| POST `/api/v1/devices/enrollment-codes` | Сессия пользователя + CSRF | `{name}` → одноразовые `id`, `code`, `expires_at`; 201 |
| DELETE `/api/v1/devices/enrollment-codes/{id}` | Владелец кода или super_admin + CSRF | Отмена кода; 204 |
| POST `/api/v1/devices/enroll` | Одноразовый code в JSON | Атомарная регистрация → `device_id`, `token`; 201 |
| GET `/api/v1/devices/{id}/state` | `Authorization: Bearer <device-token>` | Только собственные `device_id` и `settings` |
| POST `/api/v1/devices/{id}/credentials/revoke` | Владелец устройства или super_admin + CSRF | Отзыв ключа; 204 |
| POST `/api/v1/devices/{id}/credentials/rotate` | Те же права + CSRF | Новый token, старый сразу недействителен |

Код живёт пять минут, содержит 24 случайных байта и может быть использован
только один раз. В SQLite хранится только SHA-256 кода. Одновременно допускаются
пять активных кодов на владельца. Имя устройства задаётся при выдаче кода;
передавать owner_id/role и переопределять владельца при погашении нельзя.

Погашение в одной транзакции создаёт устройство, настройки и credential, помечает
код использованным и записывает аудит. Параллельное погашение одного кода создаёт
ровно одно устройство. Истёкший, использованный, отменённый, неизвестный код и
код отключённого аккаунта возвращают одинаковый 400. Публичный endpoint имеет
лимит 30 попыток в минуту на адрес клиента; счётчик сохраняется и при отказе.

Ключ устройства содержит 32 случайных байта с техническим префиксом
`smalltv_device_`. В SQLite только его хеш; исходное значение выдаётся один раз.
Повторно прочитать его нельзя. Если ответ потерян, владелец должен заменить ключ.
Безопасную передачу нового ключа физическому устройству ещё предстоит реализовать.

Cookie пользователя не заменяет ключ устройства. Ключ не даёт доступа к списку
устройств, auth API, изменению настроек или данным другого устройства. Отключение
аккаунта владельца блокирует также его устройства. Чужой device_id возвращает 404;
отсутствующий/отозванный ключ — 401. Ответ не содержит токенов, owner_id,
учётных записей или глобальной конфигурации.

## Проверка и хранение

Протокол проверен ASGI-тестами и сквозным HTTP-тестом на временной БД.
Для ручного исследования доступны существующие OpenAPI `/docs`; интерфейс панели
не расширяется без отдельного согласования функций. Не вводите реальные коды
или токены в чат, Git, URL или логи. Примеры должны использовать placeholders.
Обмен вне доверенной локальной среды требует защищённого транспорта по ТЗ;
TLS, публичный доступ и настройка Debian этим этапом не выполняются.

Резервная копия содержит хеши credentials. При restore-db в новой копии
отзываются пользовательские сессии, ключи устройств и все неиспользованные коды.
Иначе восстановление старой копии могло бы снова активировать ранее отозванный
доступ. Оригинал и сам файл backup при этом не изменяются.

В аудит попадают только типы действий и идентификаторы ресурсов. Коды, Bearer
и пароли не записываются. Автоматической очистки старых кодов/счётчиков пока нет.
Heartbeat, доставка/подтверждение событий, статус реального устройства, заводская
идентификация и provisioning Wi-Fi остаются отдельными этапами.
