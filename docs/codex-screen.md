# Постоянный экран Codex

Экран доступен в стартовых экранах, веб-пульте, Storm Bot и порядке экранов.
Работает в Storm Simulator на существующих событиях Windows-моста. Это не
монитор всех интерактивных окон Codex и не интеграция с приложением ChatGPT.
Для реальных событий запускайте прежний `local_monitor.py run-task` или
`run-smoke`; токены и регистрация агента не меняются.

Показываются статус, контурный символ-робот `>_`, длительность наблюдаемого
запуска, имя выбранного Windows-агента и время последнего события. Во время
WORKING есть спокойная анимация; prefers-reduced-motion её отключает.
Оформление учитывает четыре общих стиля, палитру и выбранный часовой пояс.
Точка доступности API остаётся отдельной от доступности Windows-моста.

## Значения

- UNKNOWN: нет агента, heartbeat не получен, данные устарели или API недоступен.
- IDLE: мост подтверждён свежим heartbeat, запусков у него ещё нет.
- WORKING: последний начатый запуск сообщил START/WORKING, мост доступен.
- DONE: получено явное завершение ответа; результат требует проверки.
- ERROR и INTERRUPTED: явные события ошибки/прерывания.
- OFFLINE: heartbeat перешёл установленный серверный порог или ключ отозван.

Потеря связи не создаёт DONE/ERROR. При устаревании основной статус меняется
на UNKNOWN, затем OFFLINE; последний отчёт сохраняется только как история.
Если неподтверждённый запуск был WORKING, его таймер скрывается. Восстановление
heartbeat само не завершает запуск. Между явно запущенными задачами локальный
мост может перестать отправлять heartbeat — это граница текущего монитора.

Длительность рассчитана по серверным started_at/updated_at, для свежего WORKING
— по текущему серверному времени. Это время наблюдения backend, не точный
секундомер CLI при отложенной доставке outbox. Время последнего события тоже
серверное. Промпт, ответ, командная строка и файлы не передаются и не отображаются.

## Проекция API

`GET /api/v1/devices/{device_id}/codex` требует пользовательскую сессию и права
на устройство. Источники берутся у владельца целевого устройства, даже если
смотрит super_admin. Сервисный agent-key не заменяет пользовательскую сессию.
Чтение выполняется в одном снимке SQLite, без heartbeat и записи событий.

Ответ: device_id, server_time, state, presence, agent_name, agent_count,
last_seen_at, пороги связи, reason и nullable run. В run — внутренний run_id,
last_reported_state, started_at, updated_at, nullable duration_seconds.
Секреты и произвольный текст заданий отсутствуют. Внутренний run_id не выводится.

Для каждого из максимум 20 агентов выбирается последний начатый запуск.
При равных секундах порядок START определяется журналом событий. Старый
незакрытый запуск не перехватывает новый; запоздалый DONE старого запуска
не завершает новый. Среди агентов приоритет у свежего WORKING, затем у
доступных мостов с последним отчётом, затем у недоступного последнего источника.
Это выбранный источник, а не утверждение о завершении всех задач всех агентов.

Симулятор читает снимок раз в три секунды только на экране Codex в видимой
вкладке, без параллельных запросов. Возраст heartbeat между ответами вычисляется
по монотонному времени браузера. Ошибка API делает статус неподтверждённым;
отказ доступа очищает частные данные. Оверлеи работают поверх текущего экрана.

## Включение и совместимость

Миграция 0023 добавляет Codex в конец списка, если в нём были включены все
четыре прежних экрана. Пользовательский порядок сохраняется. Если часть экранов
была скрыта, список не меняется: включите Codex в расширенных настройках.
Новый список по умолчанию: часы → погода → питомец → курсы → Codex.

Таблицы событий, протокол агента и ключи сохраняются. Прошивка SmallTV и
доставка снимка по device credentials не реализуются в этом этапе;
аппаратная совместимость и Debian не проверяются.
