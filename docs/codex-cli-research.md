# Storm OS — выбор источника событий Windows Monitor

Дата исследования: 2026-11-07. Это предварительное решение для первого адаптера,
не подтверждение совместимости с установленным у владельца Codex CLI.

## Проверенные источники

В [официальной документации OpenAI: non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)
описан `codex exec --json`: stdout содержит JSONL с thread/turn/item-событиями,
включая turn.started, turn.completed, turn.failed и error. Обычный вывод без
`--json` имеет другое назначение; его нельзя трактовать как поток событий.

[Документация hooks](https://learn.chatgpt.com/docs/hooks) описывает Stop/Interrupt
и Windows-команды. Stop может продолжить ход через блокирующий hook;
transcript_path не является стабильным форматом интеграции. Нельзя считать
любой Stop окончательным успешным завершением всех работ.

Эти страницы описывают текущую документацию, а не версию на машине владельца.
Настройки hooks и конфигурация Codex этим этапом не менялись.

## Результат локальной проверки

В среде агента `Get-Command codex` не нашёл команды; поиск стандартного npm-пути
ограничен доступом. Это не доказывает отсутствие CLI в обычном PowerShell владельца.
Версия, фактические flags и реальный JSONL пока не подтверждены. CLI/SDK не
устанавливались, реальные задания/модель не запускались, auth/config/transcript
файлы пользователя не читались, текущие сеансы не перехватывались.

Обновление 2026-11-08: владелец сообщил CLI 0.167.0 и успешные признаки базовых
флагов из check_cli.py. Реальные события всё ещё не проверены. Для одной ручной
проверки подготовлен [smoke_exec.py](exec-smoke.md); из среды агента он вернул not_found.

Добавлена стандартная Python-утилита `codex-monitor/check_cli.py`. Из корня проекта:

```powershell
.\.venv\Scripts\python.exe codex-monitor/check_cli.py
```

Она ищет `codex` в PATH и вызывает только `--version` и `exec --help`, с timeout
10 секунд на команду, закрытым stdin и без shell=True. Никаких prompt, ключей,
запросов Storm API или установки фонового процесса. Вывод — только JSON:

- `not_found`: команда не найдена в PATH этого процесса;
- `probe_failed`: доступ/timeout/код возврата/избыточный вывод не позволили проверить;
- `incompatible_or_unknown`: не распознана версия или не найдены нужные флаги;
- `manual_verification_required`: версия и признаки JSON/read-only в справке найдены,
  но реальное выполнение и совместимость ещё не проверены.

Код выхода 0 означает только последний вариант; остальные — 1. Поле
`real_run_checked` всегда false. Утилита не выводит путь установки, сырую справку,
stderr или текст исключения. Проверка flags — предварительная диагностика, не
версионный сертификат. Большой вывод отвергается после получения; это не
защита от намеренно вредоносного executable. Запускается CLI, выбранный обычным PATH.

## Выбранная граница первого адаптера

Для первого прототипа предлагается отдельная обёртка над явно запускаемым
`codex exec --json`. Она будет отслеживать только собственный дочерний процесс.
Она не обещает охват обычных интерактивных сессий, IDE или приложения ChatGPT.
Глобальные hooks и разбор приватных журналов не входят в первый адаптер.

Планируемые правила Storm OS (пока не код отправки):

| Наблюдение | Поведение будущей обёртки |
|---|---|
| Подтверждённое начало отслеживаемого хода | Новый run_id и START |
| Промежуточная активность | Ограниченное по частоте WORKING, без текста item |
| Подтверждённое завершение и согласованное завершение процесса | DONE для отслеживаемого хода; не оценка качества результата |
| Подтверждённый неуспешный ход | ERROR после проверки формата на установленной версии |
| Явная отмена пользователем | INTERRUPTED, если обёртка достоверно наблюдала отмену |
| EOF, пропавший процесс, повреждённый поток или несогласованные признаки | Никакого вымышленного DONE; диагностическое UNKNOWN/потеря heartbeat |

До реального теста не фиксируем окончательное сопоставление error/exit code:
промежуточная ошибка или завершение отдельного item не равны ошибке всего задания.
Необходимо проверить поведение при нескольких ходах и область одного run_id.
Обёртка должна передавать настройки безопасности явно и не расширять права Codex.

Серверный протокол [codex-events.md](codex-events.md) уже готов, но не требует
немедленного подключения. Независимо от проверки версии добавлен автономный
парсер с синтетическими тестами: [exec-parser.md](exec-parser.md). Это не проверка
реального источника. После отчёта CLI нужна безопасная проверка реального
потока в отдельной тестовой папке. Затем — отдельный этап транспорта с heartbeat,
защищённым хранением agent-ключа, устойчивой очередью и повторами с теми же event_id.
Сырые prompt/item/output/stderr на сервер не передавать и не сохранять в Git.

Настройка служб Windows/Debian, автозапуск, UI, Telegram, Tamagotchi и физическое
устройство этим этапом не затрагиваются. Перед расширением пользовательских
платформ сохраняется согласование функций.
