# Storm OS — обзорные листы состояний питомцев

Подготовлены по выбранным владельцем PNG с помощью встроенного image_gen,
без API-ключа/CLI fallback и без установки зависимостей. Это рабочие варианты
для визуального согласования, не готовый аппаратный sprite pack.

## Что сохранено

- `assets/pets/references/` — точные копии Byte.png, Glitch.png, Pixel.png и
  Null.png. SHA-256 совпадают с ранее зафиксированными исходниками; внешние
  оригиналы не изменялись.
- `assets/pets/review/Pixel-states-v2.png`, `Byte-states-v1.png`,
  `Glitch-states-v1.png`, `Null-states-v2.png` — выбранные обзорные листы.
- Pixel-states-v1.png и Null-states-v1.png оставлены как предыдущие варианты.
- `assets/pets/manifest.json` — размеры, хеши, доступ, порядок девяти состояний
  и соответствие реакциям API. Статус review_only, runtime_enabled=false.
- `assets/pets/prompts.json` — все исходные промпты, локальные относительные
  входы/выходы и отметка встроенного инструмента. Абсолютные пути профиля и
  данные аутентификации в файлах отсутствуют.

Режим и исходные промпты сохранены для воспроизводимости процесса; генерация
не гарантирует побитово одинаковый повторный результат.

## Порядок состояний

Слева направо, сверху вниз: нейтральное → радость → еда → игра → сон →
пробуждение → голод/грусть → усталость → моргание. Для Null последний кадр —
спокойный idle с сохранённой маской, а не подтверждённая анимация век.
Маска/капюшон/красный знак остаются основой образа; передача эмоций через
позу и жесты требует визуального согласования владельца.

Промежутки PNG проверены на прозрачность; цветовые значения в полностью
прозрачных пикселях не являются видимым фоном при правильном alpha compositing.
Для просмотра используйте подложку, а не оценку скрытых RGB-значений.

## Локальный просмотр

Откройте [assets/pets/review/index.html](../assets/pets/review/index.html) обычным
браузером из рабочей копии. Он работает как локальный файл: не требует backend,
сессии, ключей или внешних ресурсов. Слева исходник, справа выбранный кадр в 96×96;
есть выбор состояния и тёмной/светлой подложки, полный лист раскрывается отдельно.
Canvas только отображает PNG и не изменяет/экспортирует исходники.

Ориентир 96×96 предварительный. Листы различаются размерами/соотношением сторон,
геометрическая сетка 3×3 — подсказка для просмотра, не утверждённые точные рамки.
Для финальной анимации ещё нужны рамки/якоря, проверка соседних кадров на сдвиги,
длительности и итоговая ручная приёмка. Внешний вид согласуется раньше
технической приёмки на SmallTV.

## Доступ и оставшаяся работа

Все ресурсы расположены вне HTTP static mounts. Запросы /assets/pets/... дают 404;
Null не добавлен в общий каталог и не получает доступ автоматически по роли admin.
Метка owner_only в manifest описывает назначение, а не заменяет будущую серверную
авторизацию выдачи медиа. На данном этапе ресурсы недоступны по HTTP вообще.

После визуального согласования: подготовка точных кадров → симулятор/доставка
реакций → защищённая выдача личных ресурсов → измерения на реальном устройстве.
Встроенные кадры не доказывают ресурсы/производительность ESP8266. Бот,
загрузка пользовательских изображений и социальные функции этим этапом не добавлены.

## Проверки

Новый набор `tests/test_pet_art.py` проверяет хеши и размеры PNG, CRC чанков,
наличие alpha, отсутствие text/EXIF metadata, ограниченные относительные пути,
наличие исходников всех промптов, статус review_only и отсутствие HTTP-выдачи.
Чтение/описание PNG при подготовке выполнено уже доступным Pillow; тесты используют
стандартную библиотеку, новых runtime-зависимостей нет.
