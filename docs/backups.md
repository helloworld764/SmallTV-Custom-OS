# Storm OS — резервные копии SQLite

Локальные команды работают на Windows без SmallTV и Debian. Используется SQLite
Online Backup API, а не копирование открытого `.sqlite3` без его WAL-журнала.
Новые зависимости, HTTP-маршруты и функции веб-панели не добавлены.

## Создание копии

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m backend.app.manage backup-db
```

Источник берётся из `SMALLTV_DB_PATH`. По умолчанию создаётся новый файл
`backups/smalltv-<UTC-время>-<случайный-суффикс>.sqlite3`.
Команда не создаёт отсутствующую исходную БД, не выполняет её миграции и не
меняет записи. Backend может продолжать работать. В копию попадает согласованное
состояние SQLite; незавершённые транзакции других соединений не подтверждаются.

Другой каталог или явное имя файла:

```powershell
.\.venv\Scripts\python.exe -m backend.app.manage backup-db --directory backups/manual
.\.venv\Scripts\python.exe -m backend.app.manage backup-db --output backups/manual-copy.sqlite3
```

Существующий файл никогда не перезаписывается. Выберите другое имя для следующей
копии. Поддерживаются расширения `.sqlite3`, `.sqlite`, `.db` в нижнем регистре;
они исключены из Git. Время ожидания/работы ограничено, по умолчанию 30 секунд;
можно задать `--timeout-seconds 60` (больше нуля, не более 300).

Перед публикацией нового файла проверяются целостность, внешние ключи,
история/контрольные суммы миграций и соответствие схемы доверенным SQL-миграциям.
Файл публикуется целиком без перезаписи: rename на Windows, hard link на POSIX.
На POSIX целевая файловая система должна поддерживать hard links; небезопасной
подмены через перезаписывающий rename нет. На ошибке удаляется только временный
файл текущей операции. Исходная БД и другие копии не удаляются.

Копия сохраняется как самостоятельный SQLite-файл в режиме DELETE, без зависимости
от `-wal`/`-shm`. Режим журнала исходной базы команда не меняет.

## Проверка существующей копии

Подставьте фактическое имя созданного файла:

```powershell
.\.venv\Scripts\python.exe -m backend.app.manage verify-backup --source backups/manual-copy.sqlite3
```

Проверка открывает файл только для чтения. Повреждённые файлы, неизвестные будущие
миграции, изменённые checksums, пропуски истории, нарушенные связи, отсутствующие
таблицы и сторонние SQL-триггеры отклоняются. Пользовательские строки и хеши
паролей не печатаются. Код возврата 0 означает успешную проверку, 1 — отказ.
Проверка не является криптографическим подтверждением происхождения файла:
используйте копии из доверенного хранилища.

## Восстановление в отдельный файл

```powershell
.\.venv\Scripts\python.exe -m backend.app.manage restore-db --source backups/manual-copy.sqlite3 --output data/restored-check.sqlite3
```

Команда проверяет источник, восстанавливает его в новый файл и применяет известные
недостающие миграции только к этой новой копии. Пользователи, хеши паролей,
устройства, настройки, история аудита и другие данные сохраняются. Все восстановленные
сессии отзываются, поэтому потребуется новый вход. Ключи устройств и неиспользованные
коды привязки и ключи сервисных агентов также отзываются, чтобы старый доступ
не возобновился после восстановления.
Отметки heartbeat агентов и устройств очищаются только в восстановленной копии; после выдачи
нового ключа нужен новый heartbeat. Копия и рабочая БД сохраняют свои данные.
Устройства сохраняются, но для них потребуется выдача и передача нового ключа.
Сама резервная копия не меняется.

Нельзя указать существующий файл, настроенный рабочий путь `SMALLTV_DB_PATH` или
использовать настроенную рабочую БД как источник восстановления. Сначала выполните
`backup-db`. Автоматической замены рабочей БД, изменения `.env` и перезапуска
backend нет. Параметра `--force` нет.

Восстановление сначала проверяют на отдельной копии. Переключение приложения на
восстановленную БД — отдельное осознанное действие после остановки backend и
сохранения текущих данных. В этом этапе агент его не выполняет.

## Хранение и границы

- Копии содержат персональные данные и хеши credentials. Они **не зашифрованы**;
  `.gitignore` не заменяет защиту хранилища. Не отправляйте копии в GitHub, чат
  или общедоступные облачные папки.
- Поддерживайте несколько версий и отдельную защищённую копию вне ноутбука,
  как требует ТЗ. Выбор носителя и перенос выполняет владелец; автоматической
  отправки на другие устройства/серверы нет.
- Старые копии не удаляются автоматически. При ошибке нехватки места команда
  не подтверждает успех и не заменяет существующие файлы.
- Шифрование архивов, планировщик, ротация, off-host синхронизация и резервирование
  будущих медиа не реализованы. Сейчас резервируется только SQLite.
- Испытания внезапного отключения питания, Debian и реального SmallTV не проводились.

Для будущей локальной проверки на Linux команды те же, но вместо
`.\.venv\Scripts\python.exe` используется `.venv/bin/python`. Развёртывание на
Debian этим документом не выполняется.

Основания: [Python sqlite3.Connection.backup](https://docs.python.org/3.12/library/sqlite3.html#sqlite3.Connection.backup),
[SQLite Online Backup API](https://sqlite.org/backup.html) и
[проверки целостности SQLite](https://sqlite.org/pragma.html#pragma_integrity_check).
