# Подготовка к серверу и SmallTV

Разрешённый владельцем этап: завершить техническую подготовку существующей
системы без новых пользовательских функций и без развёртывания Debian.
Собственные питомцы и пользовательский журнал остаются отключёнными.

Проверяемые части:

- [x] Device API: отдельный ключ, данные своего владельца, лимиты/кэш/события.
- [x] Программный клиент устройства и проверки обрывов, рестарта, изоляции.
- [x] Codex Monitor: безопасный серверный HTTPS endpoint, без plaintext remote HTTP.
- [x] Компактные ресурсы для будущей прошивки и измеримый отчёт размеров.
- [x] Воспроизводимые зависимости и проверки из чистых Windows/Linux окружений.
- [x] Проверка копирования/restore и сборщик пакета без пользовательских секретов.
- [x] Инструкции запуска/обновления/восстановления и шаблоны служб без установки.
- [x] Весь Windows-набор (704), Linux (696 + 8 без Chrome), JavaScript (91), native C++.
- [x] Проверка секретных путей/токенов в подготовленных исходниках и пакете.

Результаты и команды: [verification.md](verification.md), запись от14 ноября2026.
Git-коммит и push выполняются после проверок; SHA/результат публикации указаны
в итоговом отчёте задачи, а не в самоописании этого коммита.

Плата, GPIO, контроллер LCD, Flash/RAM, Wi-Fi provisioning, безопасная прошивка/
recovery/OTA и аппаратный длительный тест остаются до получения устройства.
PlatformIO/драйвер платы до этого этапа не выбираются. Linux-проверка в WSL
не является проверкой на физическом Debian-сервере или SmallTV.

## Что подготовлено

- [Протокол данных экрана](device-display-protocol.md): JSON ≤16 KiB,
  device-only доступ, события с курсором/TTL, свои обои, публичные кадры.
- [Ресурсы](device-assets.md): 27 кадров по 17 420 байт, 166 глифов кириллицы/ASCII;
  побайтное воспроизведение каталога проверено. GPIO/драйверов платы здесь нет.
- [Monitor HTTPS](monitor-server.md): проверка CA/hostname, отказ от redirect
  и удалённого HTTP, отдельные DPAPI/outbox при смене сервера.
- [Перенос и восстановление](server-transfer.md): воспроизводимый zip с manifest,
  проверки путей/checksum, lock-файлы, backup/restore и порядок отката.

Проверки состояния программного клиента включают настоящий локальный HTTP,
30 циклов, остановку/рестарт сервера и отзыв ключа; HTTPS — отдельный локальный
сервер с временной CA. Они не отправляют сообщения настоящим пользователям
бота и не используют рабочую SQLite. Синтетический backup, созданный Windows,
восстановлен на Linux: схема 26 и прогресс сохранены, ключи отозваны.

После переноса потребуется отдельная приёмка реального HTTPS endpoint,
повторная привязка/выдача ключей после restore, проверка служб/питания/диска
на Debian и 72-часовое испытание. Готовность программного пакета не означает
завершённую прошивку или готовность системы v1 к аппаратному выпуску.
