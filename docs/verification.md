## Этап SQLite

Добавлены базовый реестр, транзакции, SQL-миграции и интеграция startup.
Для тестов использованы только отдельные временные файлы; рабочая база не менялась.

| Проверка | Результат |
|---|---|
| `.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider --basetemp=tmp/pytest-sqlite-stage-a` | 41 тест пройден |
| `node --test tests/simulator.test.mjs` | 6 тестов пройдено |
| Отдельный процесс backend на свободном loopback-порту с временной БД | HTTP health, статика и MIME .mjs проверены |
| Startup миграций и `PRAGMA integrity_check` через отдельное соединение | Пройдено |

SQLite в среде проверки: 3.53.1. Python 3.12.14, Windows.
Сохранение записей при новом экземпляре приложения и при переоткрытии БД
проверено автоматическими тестами. Неуспешная миграция откатывается вместе с DDL
и не удаляет ранее сохранённые данные.

У pytest в этой сессии нет доступа к общей временной папке пользователя и его
кэшу, поэтому выбран отдельный basetemp внутри игнорируемого tmp/ и отключён
cacheprovider. Осталось одно предупреждение Starlette о будущем отказе от httpx
в TestClient; на результат тестов оно не влияет.

Аварийное отключение питания, резервное копирование/восстановление и нагрузка
на N5000 не проверялись. Проверка HTTP выполнена на Windows, не на Debian.
Debian, ESP8266, OTA и физическое устройство не проверялись и не изменялись.
