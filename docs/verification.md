## Автономный JSONL-парсер будущей обёртки

HTTP и heartbeat. Она принимает синтетически проверенный профиль одного хода:

## Исправление размещения аргументов exec

Владелец выполнил smoke test на CLI 0.167.0: exit_code=2, ноль JSON-событий,
stderr_present=true, parser_outcome=UNKNOWN. Это не доказывает ошибку парсера;
предполагается ошибка команды запуска, но исходная причина без stderr не подтверждена.

Параметр ignore-user-config перенесён после подкоманды exec. Перед задачей
проверяется полный набор аргументов через --help без prompt в новой папке;
при отказе реальный exec не запускается. В отчёте argument_hint содержит только
известное имя флага либо null, без сырого stderr. На штатном выходе диагностический
хвост stderr дочитывается перед остановкой readers.

- `python -m pytest -q --tb=short -p no:cacheprovider --basetemp=tmp/pytest-smoke-argv`:
  **253 теста пройдено**, без skipped, 105,76 с; прежнее предупреждение httpx осталось.

## Локальный мост, очередь, heartbeat и DPAPI

Добавлены local_monitor.py, delivery.py и local_credentials.py. Существующий
smoke-процесс может передавать нормализованные события в отдельный устойчивый
outbox. Локальный HTTP-клиент проверяет identity, подтверждения и heartbeat;
редиректы/прокси/не-loopback адреса не используются. Backend, его миграции,
UI, TZ.md, AGENTS.md и пользовательская конфигурация не менялись.

- `python -m pytest -q --tb=short -p no:cacheprovider --basetemp=tmp/pytest-local-monitor-final`:
  **288 тестов пройдено, 1 skipped**, 114,76 с. Предупреждение Starlette/httpx прежнее.
- `node --test tests/panel.test.mjs tests/simulator.test.mjs tests/branding.test.mjs`:
  **25 тестов пройдено**.
- 36 новых сценариев: URL-ограничения, отсутствие редиректов, шифрованный файл и
  запрет plaintext fallback, привязка/ёмкость/повторы очереди, неизменность чужой БД,
  сетевой retry/Retry-After, постоянные ошибки/неверные ACK/identity, независимый
  heartbeat, оборванный HTTP-ответ, безопасные ошибки CLI и hooks парсера.
- Сквозной тест: локальный Python-процесс вместо модели → парсер → outbox → настоящий
  loopback HTTP → FastAPI → отдельная SQLite. Проверены DONE, presence ONLINE,
  повтор после потери подтверждения без дублей, отзыв ключа с сохранением очереди.
- `python codex-monitor/local_monitor.py check-key-store`: в среде агента
  `{"status":"dpapi_unavailable","os_code":2}`. Настоящий CryptProtectData roundtrip
  **не проверен**, этот тест помечен skipped для недоступного контекста Windows.
  Ошибка кодом 2 обнаружена в первом прогоне; plaintext-файл при ней не создаётся.
  Тесты файловых операций с внедрённым тестовым преобразованием не доказывают DPAPI.

Нужна проверка check-key-store в обычном PowerShell владельца до ввода настоящего
ключа. Утилита использует случайные байты, не обращается к модели/API и не сохраняет
ключ. Реальная авторизованная связка CLI → DPAPI → backend также ещё не проверена
в обычном сеансе владельца; код CLI запуска недоступен в среде агента.

Новых зависимостей и платных сервисов нет. Ключи и outbox исключены из Git,
добавлен *.dpapi. Рабочие credentials/БД не создавались и не менялись; тесты
использовали случайные программные ключи в изолированных временных данных.
Debian, физический SmallTV, службы Windows, Telegram/Tamagotchi и панель не
