# Storm OS — функции следующих пользовательских этапов

**Статус: базовый геймдизайн и срок 72+24 часа согласованы владельцем 8 ноября.**
Социальные механики согласованы только после основных функций, см. TZ.md v1.3.
Переключатель темы сайта реализован отдельным небольшим этапом. Игровой движок,
бот, аппаратная привязка и каталог оформления ниже ещё не реализованы.
Согласованные требования перенесены в TZ.md v1.3; AGENTS.md не менялся.
Основание — требование владельца сначала
согласовать функции Tamagotchi, Storm Bot и расширения Storm Control Panel.
Общие обязательные функции взяты из ТЗ; конкретные удобства и игровой баланс
ниже предложены разработчиком. Их можно дополнить или изменить до реализации.

## Tamagotchi — серверный движок и экран устройства

| Блок | Предлагаемые функции |
|---|---|
| Питомцы | Общие Pixel, Byte, Glitch; Null доступен только аккаунту владельца системы; собственный питомец из изображения |
| Личные данные | Один активный питомец на аккаунт; состояние выбранных питомцев сохраняется раздельно, переключение не стирает прогресс; чужие данные недоступны |
| Состояние | Сытость, энергия и настроение от 0 до 100; время последнего ухода, сон/бодрствование; серверное время как источник истины |
| Уход | Кормить, играть, уложить спать, разбудить, посмотреть состояние; понятное объяснение временно недоступного действия |
| Время и сохранение | Расчёт прошедшего времени при обращении, без постоянного тяжёлого игрового цикла; сохранение в SQLite, рестарт не обнуляет питомца |
| Повторные действия | Идемпотентные команды, cooldown, транзакционная защита от двойного нажатия и параллельных запросов |
| Свой персонаж | Фото/картинка → ввод имени → проверка и нормализация → превью имени и образа → подтверждение. Единый промпт из ТЗ также сохраняется; отклонённая загрузка не заменяет питомца |
| Отображение | На SmallTV отдельный экран; реальные шрифты/спрайты/анимации и память — после устройства; Null требует референса владельца |
| Эмоции | Каждое принятое игровое действие получает короткую реакцию: еда — удовольствие/сытость, игра — радость, сон — сонливость/ZZZ, пробуждение — потягивание; состояние голода/усталости также видно |
| Живой экран | Ненавязчивое движение на месте, редкая смена позы и короткие реплики в облачке; интенсивность/частота ограничены, пользователь может отключить реплики и уменьшить движение |
| Исчезновение | После длительного отсутствия ухода питомец пропадает; через 24 часа доступно ручное возвращение с новой игрой; имя и загруженный образ сохраняются |
| Удобства | Краткая сводка показателей, подсказка действий и подтверждение смены образа/начала новой игры; данные других пользователей недоступны |

Согласованный начальный баланс:

- Новый питомец: сытость 80, энергия 80, настроение 80.
- Бодрствование за час: сытость −4, энергия −3, настроение −2.
- Сон за час: энергия +20, сытость −2; настроение сохраняется.
- Кормление: сытость +20; игра: настроение +15, энергия −10, сытость −5.
- Кормить/играть можно в бодрствовании; для игры нужна энергия не меньше 10.
- Cooldown кормления/игры — по 60 секунд, смены сна — 10 секунд.
- Показатели ограничены 0–100; один расчёт их изменения ограничен 24 часами.
  Таймер отсутствия ухода считается отдельно по полному прошедшему времени.
- Прогресс первой игровой версии — сохранённые показатели, история ухода и
  собственные образы. Уровни/экономика/эволюция требуют отдельного решения.

Это утверждённая стартовая модель для детерминированных тестов.
Полноценная браузерная игра остаётся отложенной.

### Имя и реакции

При создании своего питомца форма/диалог обязательно запрашивает имя после
загрузки изображения. Имя можно задать и готовому персонажу. Предлагаемый лимит:
1–24 символа, кириллица поддерживается; пробелы по краям убираются, управляющие
символы/переносы/пустое имя отклоняются, вывод всегда как текст. Имя питомца
отделено от имени пользователя, имени устройства и логина. Для узкого экрана
длинное имя сокращается визуально без изменения сохранённого значения.

Реакции на принятые действия — ориентировочно 2–4 секунды, повторный callback
не запускает реакцию заново. Ошибка/отклонённое действие получает понятное
сообщение, без ложной анимации успешного кормления. Для готовых персонажей
можно подготовить несколько кадров моргания, радости, сна и грусти. Для одной
загруженной фотографии эмоция передаётся движением, значком и облачком;
новое выражение лица требует дополнительных кадров. Автоматическая генерация
новых ракурсов/поз по одному изображению не является гарантируемой функцией.

Спокойный idle, предложенный разработчиком: сдвиг на 1–2 пикселя или лёгкое
«дыхание» на 1–2% масштаба; короткое движение раз в 20–40 секунд, без резких
вспышек. Реплики — примерно раз в 2–4 минуты, облачко на 4 секунды, без повторения
одной фразы подряд. Реакции на действия и важные уведомления имеют приоритет
над случайной репликой. Во сне случайные реплики отключены. Настройки уменьшают
движение или полностью отключают облачка; индикатор backend остаётся видимым.
Примеры: «Шаг за шагом», «Ты справишься», «Время немного размяться», «Я рядом».
Фразы выбираются из локального набора по состоянию питомца, без LLM и подписки.
Точные кадры, шрифты и производительность SmallTV проверяются после доставки;
сначала логику и поведение можно проверить в симуляторе.

### Исчезновение и новая игра

Владелец задал правило «пропадает без ухода, через сутки можно вернуть».
**Согласованный порог отсутствия ухода — 72 часа.**
Кормление, игра или укладывание уставшего питомца считаются уходом, если действие
реально принято и имеет эффект. Просмотр экрана/статуса, повтор запроса и
формальное переключение сна без эффекта таймер не обновляют.

Состояния: активен → пропал → возвращение доступно → новая игра по подтверждению.
Питомец пропадает в last_care_at + 72 часа; возвращение
разрешается ещё через 24 часа, а не через сутки после первого открытия экрана.
Во время ожидания виден отсчёт. Возвращение выполняется кнопкой «Вернуть и начать
заново»: показатели становятся 80/80/80; имя, образ и привязки аккаунта остаются,
старая история не удаляется. Нужен подтверждённый запрос, автоматического сброса нет.
Перезапуск, повтор команды, переименование или замена картинки не обходят ожидание.

За 12 часов до исчезновения предлагается одно напоминание, только если пользователь
разрешил категорию Tamagotchi. Расчёт — по серверному времени, включая время
отсутствия backend; настройку паузы игры во время технического простоя нужно
согласовать отдельно, если она нужна. Новое правило заменяет прежнее предложение
о доступном уходе после любого перерыва; оно зафиксировано в TZ.md v1.3.

### Что такое социальные механики

Это взаимодействие питомцев разных людей: список друзей, просмотр открытой
карточки чужого питомца, визиты, реакции/приветствия, подарки, совместные задания.
Все перечисленные социальные механики одобрены владельцем **после основных функций**,
см. §8.5 ТЗ. Первый небольшой будущий этап — добровольные друзья и приветствие питомцу друга
с cooldown. Для него потребуются уточнение контракта, настройки видимости,
согласие на дружбу и блокировка пользователя. До завершения основных функций
социальная реализация не начинается; детали подарков/совместных заданий уточняются отдельно.

### Как будет устроен геймдизайн

Короткие заходы на уход в течение дня: увидеть состояние → выбрать нужное
действие → получить эмоцию/реплику → сохранить результат. Между действиями
питомец спокойно живёт на экране, спит или подаёт ненавязчивые признаки состояния.
Уютная пиксельная сцена 240×240 с именем, персонажем и компактными показателями;
индикатор backend постоянный, оверлеи временные. Игровые действия выполняются
через общий бот/API; браузерный симулятор остаётся инструментом проверки.
За длительное отсутствие ухода действует заданный владельцем цикл исчезновения
и нового старта. Социальные функции, экономика и эволюция потребуют отдельных этапов.

## Storm Bot — один общий Telegram-бот

| Блок | Предлагаемые функции |
|---|---|
| Меню | Устройство, Tamagotchi, Настройки, Статус, Справка |
| Привязка | Одноразовый код показывается на экране устройства и вводится в личном чате с ботом; мини-инструкция в разделе подключения; Telegram user ID связан с аккаунтом, username не используется как право доступа |
| Первый вход | Запрос имени для показа на экране, названия устройства и часового пояса; город для погоды и приветствие — необязательные шаги. Перед сохранением показывается сводка, настройки затем можно изменить |
| Устройства | Выбор своего устройства, последняя связь, UNKNOWN/ONLINE/STALE/OFFLINE; переключение экрана, яркость, тема и базовый стартовый экран |
| Честный результат | Различать «настройка сохранена на сервере» и «устройство подтвердило применение»; второе появится только с подтверждённым device-протоколом |
| Питомец | Просмотр, выбор, кормление, игра, сон/пробуждение; собственное изображение и выдача точного шаблона промпта из ТЗ через единый движок |
| Уведомления | Общая кнопка «Выключить все»/«Включить уведомления» и отдельные переключатели Codex, связи устройства/backend, Tamagotchi, системных предупреждений; дедупликация, cooldown и тихие часы |
| Удобства | Последнее выбранное устройство, быстрые кнопки ухода и яркости, кнопки «Назад»/«Обновить», ясные сообщения об ограничении частоты и устаревших данных |
| Безопасность | Проверка прав на каждой команде/callback, идемпотентность и rate limit; секреты и тексты Codex не пересылаются в статусных уведомлениях |
| Ошибки | Недоступный источник отображается как недоступный; запросы Telegram ограничены timeout/backoff, повторы не создают второе игровое действие |

По умолчанию рассылка выключена до согласия пользователя. После выключения
backend бот на нём также недоступен; обещания отправлять предупреждение из
неработающего процесса нет. До настоящего токена/аккаунта можно реализовать
доменную логику и тесты через тестовый Telegram-адаптер, явно обозначая его.

«Выключить все» работает как общий выключатель и сохраняет выбранные категории;
повторное включение возвращает прежний выбор. Пропущенные отключённые сообщения
не рассылаются пачкой. Категории отвечают за инициативные уведомления; ответы
на команды, ошибки привязки и подтверждения действий продолжают приходить.
Эти настройки не отключают обязательную точку связи на SmallTV. Предлагается
отдельно управлять облачками питомца, чтобы они не зависели от Telegram-рассылки.

Мини-инструкция в будущем разделе бота «Подключить устройство»:

1. Нажмите «Подключить устройство» в личном чате со Storm Bot.
2. Включите SmallTV с установленной Storm OS; подключите его к Wi-Fi и backend
   через первоначальную настройку.
3. Откройте режим «Привязка к боту» на устройстве; при первой настройке он
   предлагается автоматически. На дисплее появится одноразовый код.
4. Отправьте код сюда. Бот подтвердит подключение или предложит получить новый код.
5. Введите имя для показа на экране и название устройства, выберите часовой пояс.
   При желании задайте город и короткое приветствие. Проверьте сводку и подтвердите.

Это проект инструкции, а не готовая инструкция для заводской прошивки. Способ
открытия режима кнопкой/локальным UI будет определён после проверки SmallTV.
Бот до идентификации не знает, на каком устройстве показывать код: первичный
режим привязки открывается на самом устройстве. Запросить новый код из бота
можно только для уже определённого и разрешённого устройства/сеанса.

Потребуется отдельный протокол device → экран → Telegram claim: короткоживущий
одноразовый код, ограничение попыток, атомарное потребление и защита уже занятого
устройства от перепривязки. Код не содержит device-token. Текущий существующий
enrollment, где код выдаёт владелец через API, сохраняется для совместимости;
его нельзя выдавать за уже готовый экранный сценарий. До оборудования доступны
серверный контракт, тесты и явно обозначенная проверка показа в симуляторе.
Имя для экрана хранится отдельно от логина и не меняет права доступа; предложенный
лимит 1–24 символа, приветствие до 40, город необязателен и вводится явно.

В этот этап не входят персональные Tamagotchi-боты, запуск заданий Codex из
Telegram, обязательные платные API и генерация картинок локальной LLM.

## Storm Control Panel — пользователь и администратор

Вход/выход, текущие настройки, защита черновика и превью уже работают.
Ниже — полный предлагаемый набор расширений, а не утверждение об их готовности.

| Блок | Предлагаемые функции |
|---|---|
| Устройства пользователя | Список/поиск/выбор своих устройств, понятные состояния связи и последняя отметка, имя устройства, программный мастер одноразовой привязки |
| Доступ устройства | Выпуск/отмена кода привязки, ротация и отзыв device-ключа с подтверждением; выданный ключ показывается один раз, не хранится в localStorage |
| Экран и оформление | Яркость, темы и стартовый экран (готово); для каждой новой настройки — несколько готовых вариантов и собственная настройка: порядок экранов, часы, цвета, обои, уведомления и анимации |
| Тема сайта | Небольшой переключатель тёмной/светлой темы в правом верхнем углу панели, справки и страницы симулятора; выбор запоминается в браузере и не меняет тему устройства |
| Погода и часы | Город, часовой пояс, формат времени, отметка свежести погоды; источник только после проверки бесплатных условий, кэш и понятные ошибки |
| Codex | Связь агента отдельно от исторического исхода задачи, список run и ограниченный журнал без содержимого заданий; регистрация/ротация/отзыв агентов; выбор источников уведомлений для устройства |
| Питомец | Карточка состояния, выбор образа, безопасная загрузка/подтверждение медиа; полноценная интерактивная браузерная игра остаётся отложенной |
| Пользовательские уведомления | Типы, длительность и тихие часы в допустимых границах; постоянный индикатор backend сохраняется |
| Удобства | Адаптивность телефона/ПК, пагинация/поиск, фильтр событий, понятные пустые состояния, восстановление после сети, признаки «сохранено»/«применено» и защита несохранённых изменений |
| Super Admin | Пользователи/роли, все устройства/агенты, отзыв доступа, ограниченный журнал действий/ошибок, состояние backend/источников; подтверждения опасных изменений |
| Эксплуатация | Просмотр сведений о резервировании и документированный безопасный CLI-процесс восстановления; реальные метрики Debian/служб подключаются отдельно после подготовки сервера |
| После SmallTV | Версия реальной прошивки, подтверждение применения настроек, безопасные аппаратные настройки/локальный Wi-Fi provisioning и доступные обновления только после проверки оборудования |

Серверный доступ не означает автоматического доступа к паролям Wi-Fi. Локальная
страница ESP остаётся отдельным небольшим аппаратным компонентом. Кнопки OTA,
питания, SSH/systemd и произвольная командная консоль в текущий план панели не входят.
Назначение прав и восстановление БД нельзя выполнять скрыто в фоне.

«Свой вариант» — управляемый редактор/загрузка, без исполнения пользовательского
HTML/CSS/JavaScript и без произвольных шаблонов кода. Это сохраняет персонализацию
и безопасность. Аналоговые часы, шрифты, число кадров/обоев и размер медиа на ESP
остаются зависимыми от аппаратной проверки. Разнообразие сначала проверяется
в симуляторе; готовность браузерного вида не означает готовность прошивки.
