# Storm OS — выбранные владельцем образы питомцев

Владелец предоставил четыре PNG и подтвердил, что выбрал внешний вид всех
персонажей. Эти изображения являются основными визуальными референсами;
текстовые концепты используются вместе с ними, без произвольной замены образа.

Оригиналы находятся во внешней папке владельца `<ART_SOURCE_DIR>` и не изменялись.
Проверенные копии теперь сохранены в `assets/pets/references/`, вне публичной
статики. Путь профиля Windows в Git не сохраняется. Обзорные листы девяти
состояний подготовлены для просмотра: [pet-art-preparation.md](pet-art-preparation.md).
Готовый аппаратный pack и финальные кадры ещё не утверждены.

## Проверенные исходники

| Персонаж | Файл | Размер | Формат | Детали, которые нужно сохранить |
|---|---|---|---|---|
| Byte | Byte.png | 1254×1254 | PNG, RGBA 8-bit | Зелёный округлый слизень, крупные тёмные глаза, светлый блик и отдельные искорки |
| Glitch | Glitch.png | 1254×1254 | PNG, RGBA 8-bit | Сиреневый призрак, ступенчатый силуэт, улыбка, парящие частицы и фиолетовый нижний эффект |
| Null | Null.png | 1024×1536 | PNG, RGBA 8-bit | Полная фигура в тёмном капюшоне, светлая маска, красная окантовка/шнурки и красный знак на груди |
| Pixel | Pixel.png | 1254×1254 | PNG, RGBA 8-bit | Белый кот, крупная голова, жёлтые глаза, розовые нос/щёки, оранжевые уши и голубые акценты |

Все изображения успешно декодированы, имеют настоящую прозрачность и полный
видимый силуэт. Pixel занимает меньшую часть исходного холста, Null — высокий
портретный кадр: перед подготовкой общего набора нужно согласовать визуальный
масштаб, поля для движений и точку опоры, сохраняя пропорции.
У исходников есть почти непрозрачные значения alpha 253/254 и слабозаметные
краевые пиксели; при техническом экспорте проверять контур на тёмном/светлом фоне.

## Следующий художественный этап

1. Подготовить нейтральные кадры на общем холсте без растягивания персонажей;
   исходники оставить отдельно. Ориентир 96×96 на кадр предварительный.
2. По тем же образам подготовить радость/еду/игру/сон/пробуждение/грусть/усталость,
   затем моргание и спокойный idle. Эмоции и семантические события игрового API
   согласовать в одном наборе, не обещая готовую аппаратную анимацию.
3. У Null сохранить узнаваемую маску и знак: поза, наклон головы, руки и значки
   могут передавать реакцию, не меняя его личность. Тёмный костюм проверить на
   тёмном фоне; детали могут потребовать технической адаптации при уменьшении.
4. Просмотреть все состояния рядом: одинаковые пропорции, палитра, якорь,
   отсутствие обрезанных частей/прыжков масштаба и лишних персонажей.
5. Подключать готовые ресурсы в симулятор после проверки. Число кадров,
   окончательный размер, память и скорость SmallTV проверить после доставки.

Byte/Glitch/Pixel — общий каталог. Null остаётся личным питомцем владельца:
наличие референса не даёт всем пользователям/администраторам доступ к нему.
Защищённое хранение и выдача его ресурсов должны соответствовать модели доступа.
