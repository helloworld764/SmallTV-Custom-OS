# Storm OS — первый серверный этап Tamagotchi

Основание: согласованный геймдизайн TZ.md v1.3, §8.3–8.4. Реализованы чистые
правила, SQLite и защищённый API. Игровые формы, уход из UI, бот, пользовательские
медиа и социальные функции ещё не добавлены. Storm Simulator отдельно показывает
одобренные кадры и состояние питомца: [pet-display-preview.md](pet-display-preview.md).
Это не готовая игра на SmallTV и не браузерная игра.

## Границы

Первый срез — один профиль на аккаунт, Pixel/Byte/Glitch и имя 1–24 символа.
Имя нормализуется NFC/trim; управляющие и невидимые форматирующие символы запрещены.
Повторное создание даёт 409: нельзя обойти исчезновение новым именем/видом.
Коллекция и переключение сохранённых питомцев — отдельный этап с сохранением данных.
Null зарезервирован: его нет в общем каталоге, роль super_admin не даёт его всем.
Личное разрешение/референс Null, свои изображения, idle и облачка остаются отдельно.

## API

| Метод / путь | Доступ | Результат |
|---|---|---|
| GET `/api/v1/pets/catalog` | Сессия | Pixel, Byte, Glitch |
| POST `/api/v1/pets` | Сессия + CSRF | `{kind, name}`, 201 — новый профиль; 409 — уже существует |
| GET `/api/v1/pets/current` | Сессия | Собственный профиль и проекция состояния, либо 404 |
| POST `/api/v1/pets/{pet_id}/actions` | Сессия + CSRF | `{action_id, action, confirm_restart?}`, 201 — действие; 200 — точный повтор |

Действия: feed, play, sleep, wake, return. UUID action_id создаётся клиентом
один раз и повторяется при потере ответа. Только return требует явного
confirm_restart=true; для остальных true отклоняется. Время, владелец, показатели
и дополнительные поля в запросе запрещены. Device/agent Bearer не заменяет cookie.
Даже другой super_admin не играет чужим питомцем: административные/социальные
чтения потребуют отдельного ограниченного контракта.

Состояние: id/kind/name, satiety/energy/mood, sleeping, lifecycle, clock_state,
emotion, round, last_care_at, disappeared_at, return_available_at, server_time,
reaction либо null. Emotion — семантика content/hungry/tired/sad/sleepy/missing/unknown,
не готовая картинка.

Квитанция: action_id, pet_id, action, duplicate, applied_at, round, reaction.
Она подтверждает исходное действие, а не актуальное состояние. Затем читать current.
При повторе reaction=null; иное содержимое того же ID — 409. Все ответы no-store.

## Правила и время

Баланс соответствует §8.3 ТЗ. Внутренние показатели — целые единицы 1/3600 балла,
в API баллы с двумя знаками. Секундные изменения не теряются от округления.
GET не пишет состояние и не обновляет уход; частота опроса не меняет баланс.
При действии расчёт и запись атомарны. Изменение показателей за один перерыв
ограничено 24 часами, таймер отсутствия ухода не ограничен.

На ровно 72 часах — ABSENT, на 96 — RETURN_AVAILABLE. Первое открытие после
отсутствия не начинает новый отсчёт. Return с подтверждением создаёт следующий
round с 80/80/80, сохраняя ID, имя, вид и историю. Уход в этих состояниях запрещён.

Сон доступен уставшему бодрствующему питомцу, еда — не полностью сытому,
игра — при энергии от 10 и настроении ниже 100. Во сне еда/игра запрещены.
Действия без пользы дают 409 и не освежают уход. Wake меняет сон/реакцию, но
сам не считается уходом. Cooldown еды/игры 60 с раздельно, сна/пробуждения
10 с совместно; ранний запрос — 429 и Retry-After без изменения данных.

Если время сервера раньше сохранённых отметок — clock_state/lifecycle UNKNOWN,
реакции нет, новые действия дают 409. Записи не перебазируются назад.
Время игры идёт и при отсутствии backend; эксплуатационная пауза не добавлена.

## Реакции

ADOPT/FEED/PLAY/SLEEP/WAKE/RETURN имеют уникальный id, expires_at и duration_ms=3000.
Это три секунды показа после получения и отдельный TTL доставки 60 секунд.
Клиент запоминает показанный ID, учитывает срок и не продлевает анимацию повтором.
Current хранит только последнюю свежую реакцию. Последовательная доставка каждой
реакции на дисплей/симулятор и общая очередь — следующий этап; история сохранена
для будущего ограниченного протокола. Готовая аппаратная анимация не заявляется.

## SQLite и безопасность

Миграция 0008 добавляет pets, pet_states, pet_actions; 0001–0007 не менялись.
BEGIN IMMEDIATE объединяет повторную проверку сессии/активности аккаунта,
владельца, повтора, cooldown, изменение и запись истории. Выход/блокировка
в гонке с предварительной аутентификацией не позволяют выполнить действие.
Журнал ограничен 10000 принятыми действиями на профиль: затем 429 и необходим
отдельный этап архивирования/политики хранения. Точные повторы подтверждаются;
история не удаляется автоматически. Backup/restore сохраняют игру и журнал;
restore отзывает сессии/ключи по существующим правилам только в новой копии.

## Проверки

Из корня на Windows:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_pet_engine.py tests/test_pets.py tests/test_integration_http.py -q
```

Для будущей отдельной Linux-проверки — `.venv/bin/python -m pytest` с теми же путями.
Покрыты время/баланс/сон, действия без эффекта, чистые чтения, cooldown,
повторы/конфликты/параллельные запросы, рестарт, переход с 0007 и старого backup,
изоляция и гонка блокировки. Настоящий loopback HTTP-тест через JS-клиент создаёт
питомца, кормит, повторяет запрос и проверяет состояние/эмоцию. Тесты используют
временные БД/ключи/порты; Debian, Telegram и SmallTV не задействованы.
