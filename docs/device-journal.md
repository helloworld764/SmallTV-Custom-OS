# Журнал событий устройства

**Убран из продукта по указанию владельца от 12 ноября 2026.** Описание ниже —
архив реализации, не действующая функция. Импорт/подключение панели и роутера
закомментированы, `DEVICE_JOURNAL_ENABLED=False` отключает запись и живую точку
отсчёта. API отсутствует в OpenAPI и возвращает 404. Миграция 0026 и старые записи
сохранены: удаление применённой миграции сломало бы проверку истории SQLite.
Служебный audit_log безопасности не отключён. Новое управление пользователями
не разрабатывается. Сохранённые тесты журнала включают его только в изолированной
архивной fixture; отдельные проверки подтверждают отсутствие UI/API/новых записей.

В Storm Control Panel выберите устройство и раскройте **«Журнал событий»**
внизу карточки. Фильтры: все события, имя, настройки, экраны, связь и период.
Даты показываются в часовом поясе браузера, независимо от пояса дисплея.
Кнопки: «Показать», «Сбросить фильтры», «Обновить», «Показать старые события».

Первый запрос выполняется при открытии блока, по 25 записей. Открытая первая
страница обновляется раз в 15 секунд в видимой вкладке, кроме ввода фильтра/
незавершённого запроса. После загрузки старых страниц автообновление
приостанавливается, чтобы не сбить чтение; ручное обновление вернёт свежую страницу.
Изменение фильтра не смешивает разные выборки. Смена устройства, выход и отказ
доступа очищают кэш; запоздалый ответ не восстанавливает его. При сетевой ошибке
записи явно помечаются как ранее загруженные.

## Что записывается

- Фактическое переименование, без прежнего/нового имени в журнале.
- Изменённые настройки: только имена полей, без пользовательских палитр,
  имён файлов и приватных идентификаторов изображений. Для яркости пульта
  может отображаться новый процент.
- Ручной выбор экрана через пульт. Повтор request_id не создаёт новую запись,
  команды без эффекта не засоряют историю.
- Первый принятый heartbeat, устаревание/тайм-аут, восстановление.
- Отзыв/обновление ключа и предупреждение об обратном ходе серверного времени.

Бот использует те же доменные функции и журнал, новых меню Telegram нет.
Свои питомцы остаются отключёнными. **Сохранение команды на сервере не
подтверждает её показ на устройстве.** Журнал не имитирует аппаратный ACK.
Автоматическая ротация вычисляется клиентом: каждый её тик не записывается,
журналируются настройки ротации и ручные команды.

## Связь и время

История начинается после обновления до схемы 0026. Старые audit-записи и периоды
отсутствия связи не восстанавливаются задним числом. Новая точка отсчёта появляется
только после нового принятого heartbeat, даже если в старой БД были отметки.
Открытие симулятора, health, настроек и журнала не делает устройство ONLINE.
У локального превью нет настоящих heartbeat, поэтому нет выдуманной истории связи.

На каждой принятой отметке сохраняются серверное время и действовавшие пороги
STALE/OFFLINE. Между отметками чтение журнала вычисляет до двух событий по
тайм-ауту. Это отсутствие свежих данных, **не выключение питания**. GET — только
чтение, не меняет last_seen_at и таблицы. При следующем heartbeat достигнутые
тайм-ауты фиксируются вместе с восстановлением в одной транзакции.
Идентификаторы вычисленных и зафиксированных событий совпадают: чтение и
пагинация во время восстановления не создают дублей.

Нормальные частые heartbeat не записываются по одному. Отклонённые/слишком частые
отметки не создают события. При обратном ходе времени фиксируется UNKNOWN,
ложные тайм-ауты не вычисляются; следующая корректная отметка подтверждает
восстановление. Сортировка зависит от серверных часов; быстрые команды в одной
секунде дополнительно упорядочены локально для устройства.

## API, данные и безопасность

`GET /api/v1/devices/{device_id}/journal` требует сессию. Владелец видит свои
устройства, super_admin — все. Чужие/неизвестные ID дают 404, device/agent Bearer
не заменяет сессию. Ответ no-store/nosniff.

Параметры: `group=all|name|settings|screen|connection`, `since`/`until` —
включительные Unix seconds, необязательный `cursor`, `limit=1..100` (default 50).
Неверный период, фильтр и курсор дают 422. Ответ:
`{device_id, server_time, items:[{id, kind, occurred_at, details}], next_cursor}`.
Курсор — непрозрачная позиция по времени/ID, не credential; он не меняет проверку
владения. Новые записи не сдвигают старые страницы.

Миграция `0026_device_journal.sql`: история, индексы, отдельная живая точка отсчёта
heartbeat. Прежние таблицы/поля/маршруты не переименованы. Журнал не читает тексты
Codex, токены, пароли, имена пользователей или сырой audit_log. Metadata повторно
ограничивается белым списком при чтении; UI использует textContent. Автоматического
удаления истории и произвольного просмотра SQL/логов сервера нет.

Backup сохраняет зафиксированную историю. Restore в отдельную БД сохраняет её,
отзывает ключи и очищает живую точку отсчёта, чтобы не создавать из старого снимка
ложную новую связь/тайм-аут. Расчётные, ещё не зафиксированные тайм-ауты живой
отметки не переносятся как исторические факты. Рабочая БД и копии не заменяются.

## Проверки и границы

`python -m pytest tests/test_device_journal.py tests/test_advanced_panel_browser.py`
и `node --test tests/journal.test.mjs`; полный набор — по README.
Временные БД, программные heartbeat и изолированный Chrome, без реальных токенов.
Новых зависимостей нет. Для применения перезапустите локальные backend/worker,
обновите панель. БД удалять не нужно. Debian, аппаратная кнопка, питание SmallTV
и фактическая доставка команд не проверялись.
