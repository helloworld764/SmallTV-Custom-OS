# Быстрый пульт Storm Bot

В главном меню бота: **Управление** (или `/control`). Выберите своё устройство.
Выбор общий с разделом «Мои устройства», поэтому кнопки старого пульта после
смены устройства перестают действовать.

- «Назад»/«Вперёд» переключают по кругу: часы → погода → питомец → курсы.
- Прямые кнопки открывают один из этих экранов.
- «Темнее»/«Ярче» изменяют яркость на 10 пунктов в пределах 0–100.
- «Главный экран» возвращает к выбранному стартовому экрану.
- «Обновить» перечитывает состояние; «Выбрать устройство» открывает список своих.

В карточке показываются имя, выбранный экран, яркость и реальная серверная
оценка связи устройства. Для локального превью есть отдельная подпись;
открытие симулятора или команда пульта не делают устройство ONLINE.
Мониторинг и Codex пока исключены из круга и прямых кнопок как незавершённые
экраны. Если они выбраны стартовыми в прежних настройках, «Главный экран»
может открыть соответствующую явно обозначенную заглушку.

Кнопки действуют до 5 минут. После нажатия бот редактирует ту же карточку через
`editMessageText`. Новые сообщения для переходов, яркости, обновления и выбора
устройства не создаются. Повторная доставка одного Telegram update не выполняет
команду второй раз; два настоящих нажатия с разными update_id выполняют две
команды, даже если второе пришло до обновления клавиатуры. Идемпотентный UUID
команды производен от Telegram user/update_id, а не от переиспользуемой кнопки.
Проверки владельца, выбранного устройства, активности аккаунта и срока кнопки
выполняются на сервере. Переход в пульт отменяет ввод города/имени питомца/яркости.

## API и данные

`POST /api/v1/devices/{id}/control`, пользовательская сессия и CSRF:

```json
{"request_id":"00000000-0000-4000-8000-000000000001","action":"next"}
```

Действия: `next`, `previous`, `screen`, `dimmer`, `brighter`, `home`.
Для `screen` обязательно поле `screen` из `clock/weather/tamagotchi/markets`;
для прочих действий поле не передаётся. Идентификатор — UUID, новый для нового
действия. Повтор одинакового запроса в течение 24 часов возвращает записанный
результат с `replayed:true`; повтор UUID с другим телом/устройством даёт 409.
Результат повтора является снимком исходной команды: актуальные настройки
читаются через существующий GET settings. Права проверяются до чтения повтора.
Старые записи дедупликации удаляются после 24 часов при следующей команде.

Миграция 0020 добавляет nullable `device_settings.current_screen` и таблицу
`device_control_requests`. Старые столбцы, стартовый экран, питомцы, настройки
и миграции сохраняются. NULL означает следование `start_screen`. Явное значение
переключает текущую серверную проекцию независимо от старта; `home` снова
устанавливает NULL. Значение переживает перезапуск backend. Как именно
аппаратная прошивка будет сбрасывать экран при включении, проверим отдельно.

Команды и дедупликация записываются одной транзакцией SQLite; относительные
операции используют актуальную строку под блокировкой записи. API допускает
обычного владельца и super_admin согласно существующей модели; бот даже для
super_admin ограничен собственными устройствами. Команды не подтверждают
физическую доставку. Ответ `saved_on_server:true` означает сохранение на сервере.

Симулятор получает `current_screen` из того же API, применяет его при следующем
успешном опросе. В видимой авторизованной вкладке настройки запрашиваются раз
в секунду без параллельных запросов; health и уведомления сохраняют прежнюю
периодичность. При ошибке быстрый опрос останавливается до обычного восстановления,
в фоновой вкладке он не работает. Задержка сети добавляется к интервалу опроса.
Локальные часы, погода, питомец и курсы
используют активный экран; оформление и стартовый экран остаются независимыми.
При сетевом сбое сохраняется последняя проекция с отметкой устаревания;
при отказе доступа она сбрасывается. API `/state` для device credentials также
содержит новое поле, но аппаратная интеграция не считается выполненной.

Для проверки: запустить backend и бот, `/start` → «Управление», выбрать своё
превью, открыть симулятор из панели и нажать стрелку/прямую кнопку. Изменение
стартового экрана в настройках не отменяет уже выбранный активный экран;
для возврата к стартовому используйте «Главный экран».

## Обновление пульта без новых сообщений

Миграция 0021 добавляет nullable `telegram_replies.edit_message_id`. Цель
редактирования берётся только из доверенного сообщения текущего бота в личном
чате нажавшего пользователя, с проверкой bot_id и положительного message_id.
Данные других чатов/ботов и недоступные сообщения не допускаются к управлению.
Для одной карточки ожидающий ответ заменяется более новым. Outbox сохраняет
редактирование при временной сетевой ошибке/429; ошибки 400 (включая уже
применённое редактирование или удалённое сообщение) не создают новое сообщение
и не отключают уведомления. При удалении карточки откройте «Управление» заново.

Рабочий процесс подтверждает callback до обработки команды (тайм-аут ACK —
3 секунды) и доставляет редактирование после каждого update, без ожидания конца пакета.
Карточка успешного действия сохраняет высоту, без добавления служебного абзаца.
Непрерывное получение Telegram updates остаётся long polling; его timeout 25 с
не является задержкой каждого нажатия — Telegram возвращает новые события сразу.
