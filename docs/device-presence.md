# Storm OS — серверный heartbeat устройства

Реализован программный контракт доступности отдельного клиента устройства.
Он тестируется на Windows без SmallTV, прошивки и Debian. Новых элементов панели
и автоматического heartbeat браузерного симулятора нет: открытая вкладка не должна
выдавать себя за физическое устройство. Доступность API через `/health`, связь
Windows-агента и связь устройства — независимые состояния.

## API

| Метод / маршрут | Доступ | Результат |
|---|---|---|
| POST `/api/v1/devices/{id}/heartbeat` | Bearer-ключ именно этого устройства | Только `{}`, 204 без тела |
| GET `/api/v1/devices/{id}/presence` | Сессия владельца или super_admin | Состояние и серверные отметки времени |

Чтение возвращает `device_id`, `state`, `last_seen_at` (Unix seconds либо null),
`server_time`, `stale_after_seconds`, `offline_after_seconds`. Ответы не кэшируются.
Чужое/несуществующее устройство при чтении даёт 404. Ключ другого устройства
при отправке также даёт 404; cookie или ключ Windows-агента не заменяет device Bearer.
Для чтения Bearer не заменяет пользовательскую сессию. CSRF для heartbeat не нужен,
поскольку авторизация выполняется отдельным Bearer, а не браузерной cookie.

Клиент не задаёт время, статус, владельца и идентичность в JSON: дополнительные
поля отклоняются с 422. Сервер повторно проверяет ключ и активность владельца
под `BEGIN IMMEDIATE`, чтобы отзыв/ротация между аутентификацией и записью
не позволили устаревшему ключу освежить отметку.

## Свежесть

| Условие | state |
|---|---|
| Ключ не выдавался или heartbeat ещё не поступал | UNKNOWN |
| Отметка находится в будущем относительно часов сервера | UNKNOWN |
| Возраст меньше stale-порога | ONLINE |
| Возраст от stale до offline, не включая offline | STALE |
| Возраст равен offline-порогу или больше | OFFLINE |
| Выданный ключ отозван или его владелец неактивен | OFFLINE |

`SMALLTV_DEVICE_STALE_SECONDS`: по умолчанию 30, диапазон 10–3600.
`SMALLTV_DEVICE_OFFLINE_SECONDS`: по умолчанию 90, диапазон 15–86400,
строго больше stale. Ошибка конфигурации останавливает запуск. Пороги вычисляются
при чтении без фоновой службы. ONLINE означает недавний принятый запрос,
а OFFLINE — истечение срока/недоступный доступ, не доказанное выключение питания.

Не чаще одной записи в 5 секунд на устройство. Ранний повтор возвращает 429
и `Retry-After`, не обновляя время. Ориентир будущего клиента — heartbeat раз
в 10 секунд с timeout/backoff. Пропущенные heartbeat не накапливать в очередь:
после восстановления отправить один новый запрос. Ограничение записей не заменяет
сетевую защиту будущего развёртывания.

GET state/settings, `/health` и открытие симулятора отметку не обновляют.
При переводе серверных часов назад состояние UNKNOWN до нового heartbeat.
Ни получение настроек, ни ONLINE не являются подтверждением применения настроек
к экрану или аппаратной совместимости.

## Хранение и проверки

Миграция `0007_device_presence.sql` добавляет одну строку на устройство, с FK
и неотрицательной серверной отметкой. Миграции 0001–0006 и существующие записи
не меняются. Перезапуск сохраняет отметку; ротация/отзыв ключа очищают её.
Восстановление в новый файл отзывает ключи и удаляет heartbeat только в новой копии.
Рабочая БД и исходный backup остаются неизменными. Ключ после ротации должен
отправить новый heartbeat. Не накапливаются история heartbeat и строки аудита
на каждый пинг.

Запуск из корня на Windows:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_device_presence.py -q
```

На Debian (инструкция для будущей отдельной проверки, без развёртывания):

```bash
.venv/bin/python -m pytest tests/test_device_presence.py -q
```

Тесты используют временные БД и генерируемые ключи; проверяют границы порогов,
чужие credentials, RBAC, отзыв/ротацию/блокировку владельца, гонку с аутентификацией,
параллельные запросы, рестарт, перевод времени назад, upgrade с шестой миграции
и восстановление старой копии. Есть настоящий HTTP-тест на выделенном loopback-порту,
с остановкой тестового сервера; рабочий backend и реальные ключи не используются.
