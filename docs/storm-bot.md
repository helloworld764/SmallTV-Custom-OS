# Storm Bot — первый локальный этап

Реализованы главное меню, привязка Telegram к существующему аккаунту, выбор
своего устройства, общий с панелью город погоды и настройки будущей рассылки.
Рабочий процесс запускается явно на Windows через long polling, отдельно от
FastAPI. Backend и worker используют один и тот же `SMALLTV_DB_PATH`.
Новых зависимостей нет. На Debian ничего не настраивается и не запускается.

## Что доступно

- Меню «Мои устройства», «Питомец», «Настройки», «Помощь» и кнопки возврата
  через постоянное меню. Команды `/start`, `/devices`, `/settings`, `/city`,
  `/notifications`, `/pet` работают в личном чате.
- Код из защищённой панели связывает Telegram user ID с текущим аккаунтом.
  Имя Telegram/username не даёт прав. Автоматической регистрации аккаунтов нет.
- Список первых 25 собственных устройств и сохранение выбранного устройства.
  Даже super_admin через бота не получает чужие устройства. Выбор повторно
  проверяет владельца; переключение экранов и аппаратное подтверждение пока
  не реализованы. При большем количестве устройств понадобится пагинация.
- Изменение города через кнопку или `/city название`. Поиск и хранение общие
  с веб-панелью. Ошибка поиска сохраняет прежний город.
- Главный выключатель уведомлений и категории Codex, связь, питомец, система.
  По умолчанию рассылка выключена. Главный выключатель сохраняет выбор категорий.
  Подключено уведомление о полном часовом сне: [timed-pet-sleep.md](timed-pet-sleep.md).
  Остальные инициативные события пока не отправляются. Ответы на команды
  не зависят от выключателя.
- Карточка питомца с изображением, показателями, созданием и кнопками ухода
  добавлена отдельным этапом: [bot-pet-care.md](bot-pet-care.md).
- Отвязка в панели или с подтверждением в боте. Она отменяет коды, очередь
  приватных ответов и согласие на рассылку, сохраняя выбор категорий.

## Запуск на Windows

Из корня рабочей копии:

1. Добавьте в **локальный** `.env` строку `SMALLTV_TELEGRAM_BOT_TOKEN=...`,
   вставив вместо многоточия токен из BotFather. Не отправляйте его в чат,
   командную строку или Git. Существующий `.env` не заменяйте примером целиком.
2. Остановите backend через Ctrl+C и запустите снова:

   ```powershell
   .\.venv\Scripts\python.exe -m backend.app
   ```

3. В другом PowerShell из того же каталога проверьте только конфигурацию:

   ```powershell
   .\.venv\Scripts\python.exe -m backend.app.bot_worker check
   ```

   Команда не обращается к Telegram и не печатает токен. Без токена она
   возвращает код 1 и `token_configured: false` — это ожидаемо.

4. Явно запустите Telegram-процесс:

   ```powershell
   .\.venv\Scripts\python.exe -m backend.app.bot_worker run
   ```

   Остановка — Ctrl+C. Webhook должен отсутствовать: worker проверяет его,
   но не удаляет. Одновременно разрешён один worker для этой SQLite-базы.
   Первая успешная инициализация закрепляет bot ID в базе; подмена токена
   токеном другого бота отклоняется. Для смены бота понадобится отдельная
   процедура переноса/отвязки; не удаляйте базу.

5. Войдите в `/panel/`, обновите страницу Ctrl+F5. В разделе Telegram нажмите
   «Получить код». В личном чате со своим ботом отправьте показанную команду
   `/link код`. Нажмите «Обновить статус» в панели.
6. Проверьте выбор своего устройства, изменение города и сохранение города
   в панели. Проверьте выключатель и категории уведомлений, затем отвязку.

Код действует 5 минут, показывается только в ответе выдачи, хранится в БД
как хеш и потребляется атомарно. Повторная выдача ограничена 30 секундами;
новая выдача отменяет предыдущий код. Для ошибок ввода есть лимит попыток.
Код и команда не сохраняются в браузерном хранилище или в журнале worker.

Это **привязка аккаунта через панель**, а не код на экране SmallTV.
Существующий device enrollment не изменён. Устройство → экранный код → бот,
инструкция аппаратной настройки и запрос имени для экрана остаются отдельным
этапом после протокола и проверки прошивки/симулятора этого сценария.

## API и хранение

- `GET /api/v1/telegram/status` — текущая сессия; статус связи и категории.
- `POST /api/v1/telegram/link-code` — сессия + CSRF, ответ с кодом один раз.
- `DELETE /api/v1/telegram/link-code` — сессия + CSRF, отмена кода.
- `DELETE /api/v1/telegram/link` — сессия + CSRF, отвязка.

API не раскрывает Telegram ID и не принимает внешние Telegram updates.
Updates получает только локальный worker по HTTPS от Telegram. Группы,
пересланные/отредактированные сообщения и отправители-боты отвергаются.
На каждой операции проверяется активность локального аккаунта.
Миграция 0010 добавляет отдельные таблицы; прежние данные не перезаписываются.
Восстановление backup отзывает Telegram-привязки и коды и очищает ответы.
SQLite теперь содержит Telegram ID, как и остальные данные аккаунта, и остаётся
исключённой из Git. Полные Telegram updates/переписка не сохраняются.

Повторный update_id не повторяет изменение. Offset и очередь ответов хранятся
в SQLite; приватный ответ перед отправкой снова проверяет связь и активность.
Ответы истекают через 5 минут, очередь ограничена 10 ответами на чат.
При обрыве после принятия сообщения Telegram, но до удаления из очереди,
ответ может повториться: Telegram sendMessage не предоставляет ключа
идемпотентности. Команда при этом повторно не применяется. Уже отправленный
ответ нельзя отозвать отвязкой. Тексты исключений провайдера не печатаются,
поскольку URL Telegram содержит токен. Timeout, backoff и Retry-After ограничены.

Контракт проверен по [официальному Telegram Bot API](https://core.telegram.org/bots/api):
getUpdates, getMe, getWebhookInfo, sendMessage, answerCallbackQuery.
Живой Telegram не считается проверенным до запуска с токеном владельца.

## Проверки без токена

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_telegram.py tests/test_weather.py
node --test tests/panel.test.mjs
```

Тестовый Telegram-адаптер не обращается в сеть. Он проверяет личный чат,
однократность/срок кода, CSRF, изоляцию владельцев, отзыв прав, категории,
погоду, обработку повторов, offset, очередь, ошибку Telegram, webhook,
единственный процесс, маскирование токена и отзыв связи после restore.
