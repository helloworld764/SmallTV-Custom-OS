# Storm Bot — карточка питомца и уход

Загрузка/промпт своего образа временно отключены. Код и сохранённые изображения
не удалены, в карточке работают базовый персонаж и прежний уход.
Статус: [custom-pets.md](custom-pets.md).

Бот использует те же доменные операции `adopt_owned`/`act_owned`, что HTTP API.
Баланс, API-маршруты, существующие профили, 72 часа до исчезновения и 24 часа
до возвращения сохранены. Состояние после действия читается из того же SQLite,
поэтому эмоция поступает в авторизованный Storm Simulator через прежний API.

## Пользовательский сценарий

1. В личном чате связанного аккаунта нажмите «Питомец» или отправьте `/pet`.
2. Если питомца нет: «Создать питомца» → Pixel/Byte/Glitch → введите имя
   от 1 до 24 символов. На ввод есть 5 минут. Можно отменить или перейти
   в другой раздел; чужие сообщения/кнопки не создают профиль другому человеку.
3. Карточка содержит изображение, имя, образ, сытость, энергию, настроение
   и состояние. «Обновить» перечитывает состояние без изменения времени ухода.
4. Бодрствующему питомцу доступны «Кормить», «Играть», «Спать»; спящему —
   «Разбудить». Ограничения движка объясняются по-русски, включая cooldown.
5. После принятого действия возвращается свежая карточка и кадр реакции.
   Переключите своё устройство в симуляторе на Tamagotchi: тот же профиль
   и свежая реакция доступны через `GET /api/v1/pets/current`.
6. Исчезнувшему питомцу показывается оставшееся время. После срока появляется
   «Вернуть» → отдельное подтверждение. Новый старт сохраняет ID, имя и вид,
   возвращает показатели к 80/100 и увеличивает номер старта. «Отмена» отзывает
   текущие подтверждения. Созданием другого образа исчезновение не обходится.

Загрузка своих изображений, имя и превью добавлены отдельным этапом:
[custom-pets.md](custom-pets.md). Личный Null из локальных ресурсов, коллекция, социальные функции,
прочая инициативная рассылка и аппаратная прошивка в этот этап не входят.
Уведомление о завершении часового сна добавлено отдельно:
[timed-pet-sleep.md](timed-pet-sleep.md).

## Обновление локальной рабочей версии

Остановите **оба процесса** backend и bot worker через Ctrl+C. Запустите backend
снова, затем worker в отдельном PowerShell из того же корня проекта:

```powershell
.\.venv\Scripts\python.exe -m backend.app
```

```powershell
.\.venv\Scripts\python.exe -m backend.app.bot_worker run
```

Миграция 0011 применяется при запуске. `.env`, Telegram-привязка и существующий
питомец сохраняются. Новые зависимости для запуска не нужны.
Откройте новую карточку «Питомец» в боте. Старые сообщения не заменяются:
их кнопки ограничены сроком действия.

## Повторы и доступ

Кнопка ухода содержит случайный идентификатор намерения; владелец, питомец,
тип действия, номер старта и срок 5 минут хранятся на сервере. Сам callback
не задаёт владельца/показатели/время. Проверяется актуальная Telegram-привязка
и активность аккаунта. Повтор update_id не исполняется; повтор нажатия той же
кнопки использует тот же action_id и не повторяет игровой эффект.
Другая кнопка тоже подчиняется cooldown. На аккаунт хранится не более 60
свежих намерений, а авторитетная история игровых действий не удаляется.

Отвязка и restore очищают черновики, намерения и приватную очередь ответов.
Игровой профиль и история остаются. Ответ/фото перед отправкой повторно
проверяет активность и привязку пользователя. Доставка Telegram может
повторить ответ после сетевой неопределённости, но не игровое действие.

## Изображения

27 готовых картинок 960×960 получены из одобренных публичных листов Pixel,
Byte и Glitch и лежат в `web/simulator/pets/bot/`. Исходники не изменены.
Это кадры для бота, не аппаратные спрайты. Таблица имён `photo_path` допускает
только эти 3×9 ресурсов: никакие присланные пути, файлы пользователя или Null
не читаются. PNG содержат только изображение; хеши и источники — в manifest.
Фото отправляются через [Telegram sendPhoto](https://core.telegram.org/bots/api#sendphoto),
как multipart, с короткой подписью и inline-кнопками. При отсутствии локального
кадра карточка остаётся текстовой. Очередь хранит ключ ресурса, а не файл/URL.
Размер увеличен с 320×320, чтобы Telegram не растягивал маленькую картинку.
Масштабирование NEAREST сохраняет чёткие пиксельные границы; исходные детали
не перерисовываются. Telegram по-прежнему может сжимать фото при доставке.

Для повторной подготовки ресурсов есть `tools/build_bot_pet_photos.py`.
Готовые картинки каталога включены в Git. Pillow также используется при загрузке
пользовательских изображений: обработка и Telegram-превью выполняются один раз,
готовый PNG хранится приватно в SQLite, не публикуется в статическом каталоге.

## Проверки

`tests/test_telegram.py` проверяет создание, имя, отмену/срок черновика,
уход, cooldown, сон, двойное нажатие, устаревшую/чужую кнопку, исчезновение,
подтверждение возвращения, общий HTTP API и передачу фото тестовому адаптеру.
`tests/test_pets.py` сохраняет проверки прежнего HTTP-контракта и гонок.
`tests/test_pet_art.py` проверяет комплект, размеры и хеши новых картинок,
отсутствие метаданных и сохранность исходников. Тесты не отправляют сообщения
в живой Telegram и не меняют рабочую БД. Реальная доставка проверяется отдельно.
