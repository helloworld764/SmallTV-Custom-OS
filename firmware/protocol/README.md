# Протокол Storm OS до выбора платы

`display-v1.schema.json` и `events-v1.schema.json` описывают существующие JSON
envelopes. Исходник host-валидатора: `firmware/tools/protocol_contract.py`.
Pydantic нужен только инструментам/тестам Windows/Linux, не микроконтроллеру.
Серверные маршруты, JSON-ключи и авторизация не менялись.

```powershell
.\.venv\Scripts\python.exe tools/export_device_contract.py
# Воспроизведение в новом каталоге, без замены существующих файлов:
.\.venv\Scripts\python.exe tools/export_device_contract.py --write --directory tmp/contract-export
```

На Linux заменить python-путь на `.venv/bin/python`. Новые поля версии1
считаются additive и могут игнорироваться; обязательные поля, типы и
schema_version проверяются. Bool не считается целочисленным курсором.
Общий лимит JSON16384байта проверяется до декодирования; дубли JSON-ключей,
NaN/Infinity и чужой device_id отклоняются. Пустой список событий нормален;
он не означает DONE. Весь ответ принимается атомарно до сохранения курсора.

`data` остаётся контрактом соответствующего экрана: weather/forecast, pets,
Codex или markets. Эти схемы не подменяют семантические правила экрана:
available=false, UNKNOWN/STALE, время сна и отсутствие агента сохраняют смысл.
Нельзя подставлять «успех», если часть данных недоступна.

Правила клиента:

1. Проверить TLS и свой ключ; запросы с timeout, без автоматической передачи
   Authorization на redirect. Сертификат/время не подтверждены — ключ не отправлять.
2. Начать UNKNOWN. Только корректный ответ своего устройства подтверждает API;
   недоступность погоды или агента не доказывает отключение самого API.
3. Опрос обычного снимка —5с, backoff при ошибках; учитывать429/Retry-After.
   GET не заменяет POST heartbeat и не подтверждает применение настроек платой.
4. После обрыва хранить лишь ограниченный устаревший снимок;401/403 очищают
   приватные данные. После восстановления БД курсор сервера может уменьшиться.
5. TTL уведомления уменьшать временем в пути; дедупликация по id, ERROR выше
   обычного завершения, затем возврат на прежний экран. Настройки/кэш в Flash
   сохранять только при изменениях, не каждый цикл.

`raster.h` проверяет только STP1. Размер/палитра/индексы ограничены; буфер полного
RGB-экрана не выделяется. Это не transport/TLS/LCD-драйвер и не firmware.bin.
Приёмка устройства: [first-device-check.md](../../docs/first-device-check.md).

## Проверка portable-сборки до устройства

На Linux с уже установленным g++ из корня проекта (без установки пакетов):

```bash
storm_check_dir=$(mktemp -d)
g++ -std=c++17 -Wall -Wextra -Werror -pedantic tests/native_raster.cpp -o "$storm_check_dir/raster-check"
"$storm_check_dir/raster-check" firmware/assets/catalog-v1/Pixel-neutral.spt
```

Успешное завершение0 проверяет parser/границы/строки STP1, не сборку Xtensa.
Windows без C++-компилятора может использовать имеющийся WSL для этого шага;
Windows Python/JS/браузерные тесты запускаются как в README.
Настоящая firmware-сборка появится только после выбора подтверждённой платы,
закрепления toolchain/драйвера и проверки безопасного восстановления.
